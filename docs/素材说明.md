# 素材说明

> 记录作品里用到的非代码素材、来源与授权状态。**评审看得到这一页**，所以宁可写清楚。

## 一、角色立绘（2 张）

| 文件 | 用途 | 尺寸 | 体积 |
|---|---|---|---|
| `public/art/student-academic.webp` | 入场界面左侧 | 252×640 | 30 KB |
| `public/art/student-sporty.webp` | 入场界面右侧 | 333×640 | 47 KB |

**来源**：AI 生成（**第 2 版，2026-09-20**），非来自任何现有作品或商业素材库。

> 第 1 版于 2026-09-16 生成，因质量不达标（眼睛无瞳孔、姿态僵硬、背景带独立色块导致无法抠图）已整体废弃重做。**两版均为本机离线生成**，未把任何素材上传到第三方服务。

**生成环境**（第 2 版）：本机 Stable Diffusion WebUI（秋叶整合包 v4.10）＋ `anything-v5` 模型，通过其 HTTP API 批量出图，每个角色跑 4 个随机种子共 8 张候选，再逐一比对挑选。

**生成时的设定**：
- 同一个人的两种可能——左侧偏学术（深蓝制服 + 青色点缀 + 眼镜 + 书），右侧偏运动（运动服 + 琥珀色点缀 + 马尾 + 篮球）
- 配色限定为终端的四个色（深蓝 / 青 / 琥珀 / 米白），保证与界面同一套色系
- 平涂（cel shading）+ 清晰线稿，便于在深色背景上观感干净
- 背景要求为**中性纯灰**，这是抠图能成立的前提（见下方「后处理」）

**后处理**：
1. **纯灰背景分离** → 透明通道。判据是「低饱和 + 亮度贴近背景 + 与画面外边界连通」三条同时成立，再叠加一步「只保留最大连通域」清除漂浮残渣
2. 按角色包围盒裁掉多余留白
3. 缩放并转 WebP

> 第 1 版曾用「四角泛洪」抠图，遇到两个结构性障碍：背景是**彩色渐变**（泛洪会在渐变处停下，沿轮廓留一圈青色鬼影）、以及**背景色与角色配色同色系**（青绿背景 + 青绿角色，任何容差都必然误伤角色）。第 2 版把背景改为中性灰后，改用饱和度与亮度双条件判据，两个问题一并解决。

**AI 生成内容的声明**：
- 本作品的角色立绘由 AI 生成，此处以文字形式显式声明其生成来源
- 除此之外，作品未使用任何第三方美术、音乐、语音素材
- 界面文案中不出现任何现有商业作品的专有名词；视觉风格为通用的「深色仪表盘 + 等宽字 + 扫描线」语言，不复制任何具体作品的标识、制服或徽记

## 二、界面图形

界面上的网格、扫描线、铰角面板、六边形纹章、属性双向条**全部由 CSS / SVG 手写**（见 `src/index.css` 的 `.term-*` 与 `src/scenes/IntroScene.jsx` 的 `<Crest>`），不含任何图片资源。

## 三、数据

- `public/data/问卷基准数据.csv`：**模拟生成**的 2000 行人群数据，非真实调查结果
- `public/data/示例-班级问卷.csv`：**模拟生成**的 48 人班级数据
- 两者均由 `scripts/generate-survey-data.py` 按 `src/data/matrix.json` 的选项池加权采样产生，页面与 README 中均已声明"模拟数据"

## 四、字体

只使用系统字体（`system-ui` / `Segoe UI` / `Microsoft YaHei` 等）与系统等宽字体，**不引入任何外部字体文件**。

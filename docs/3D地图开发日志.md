## 三、关键结论（别再重走）

1. **段拼接不可能同时满足「不重叠」和「无缝」**：加长 ⇒ 共面 z-fighting；精确相接 ⇒ 斜角缝；补块 ⇒ 色块/全局污染。最终解是**取消拼接**，整张路网用 canvas 一次画完贴到单一平面。
2. **「掉入虚空」先查支撑高度表**，别急着加实体：`floorAt()` 与渲染平台顶面不一致才是真因（`walkSurfaces` 原来只登记 `y>2` 的高台）。
3. **多年修不好的建筑闪烁要数共面对**：实测 500 对跨批次共面，按材质给确定性 `polygonOffset` 深度层级，覆盖全部建筑类型，不逐栋调。
4. **「画面糊」先量 canvas 实际尺寸 / dpr**，别猜贴图：`waterTick` 让静止帧长期走移动档、iframe 强制 low 档是主因。
5. **God rays 恒为 0 的真因**：`post.render(scene,camera)` 漏传第三参 `sunWorld` → `sunVis=0`；且不能依赖画面里恰好有太阳，要用解析式光源 + 场景遮挡；俯视相机朝下时太阳必然 behind，需要艺术化回退源才看得见效果。历史注释误判为「采样循环问题」。
6. **验证视角由用户指定**：他要的是**第一人称步行**，不是车内视角；只用第三人称俯视或车内视角验收等于没验。
7. **像素差 MAD 受相机位移与水面动画主导**，判定闪烁/清晰度要靠连续帧目视 + 几何/配置断言。
8. **用户说「回退 / 别加东西」就别顺手再修**；局部修补一旦扩散到全图，优先整体回退到他认可的基线。
9. **可见版本角标必须进发布流程自动同步**，手改一次必忘。
10. 用户报「文件被改 / 变形」时，先核对时间戳 + 两版并排真读，多半是刷新撞上旧版本缓存。

## 七、2026-11-10 树冠发黑与水面重做（v30.2）

用户反馈「加入光影后树木被光照到发黑」并要求水面更灵动。**改动只动材质与贴图，不动几何、布局、光照参数。**

### 树冠发黑：两个独立原因

1. **高画质：叶背只剩环境光。** 树冠是几百片随机朝向的裁切叶片，`MeshLambertMaterial` 只算直接光，
   背光叶片只剩半球环境光；树冠一密，远看核心就是近黑。修法是在 canopy / canopyLow 的
   `output_fragment` 前补一层**按反照率的透射项**（`outgoingLight += diffuseColor.rgb * 0.40`），
   颜色仍随实例色、顶点色、叶贴图走，金黄与枫红的树不会被染成灰绿。
   同机位实测（宿舍区，树冠放大 3×）：近黑像素 **3.6% → 0.3%**，meanLum 110 → 113.5。
2. **省电档：低模几何缺 color 属性。** `trunkLow`（裸 Cylinder）与 `treeLow`（裸 Icosahedron）
   没有 `color` 属性，而 trunk / foliage 材质开了 `vertexColors` —— WebGL 按默认 (0,0,0) 取色，
   整棵树与树干渲染成**纯黑**。已在 `createVegetationGeometries` 里补中性顶点色（tint），
   省电档黑块恢复为橄榄/桃色与棕色树干。

验证：daylight / overcast / golden / dusk 四档光照实拍，树冠均为绿色层次、无纯黑；
近景独立相机贴脸渲染仍是正常绿叶，未发灰；省电档同一机位复测黑块消失。控制台 0 报错。

### 水面：从「水泥板」到可读的水

原状是 1024×512 径向渐变（外圈 #a5b59a）+ 一个几乎看不见的滚动相位；在暖阳与 ACES 下外圈直接过曝，
湖看起来像一块浅色水泥。改动：

- **贴图重画**：改为对角加深的静水底色（#2f574f→#5c8577），叠低频深浅斑块、细波纹与一层很薄的天光反射。
- **波法线**：四组不同波长/方向的正弦波（坡度合计约 0.2），在片元着色器里扰动世界空间法线。
- **流动色带**：采样坐标先做域扭曲，再叠两条不同速度的色带与顺流反光条；细节按距离淡出，避免俯视摩尔纹。
- **碎光**：两列交叉波的高次幂产生的零散亮点，只在近处出现。
- **菲涅尔**：掠射角混入天光色（线性强度 0.30），并用波面调制反射强度 —— 反光随水波闪动，而不是一层均匀薄膜；俯视时 fres 接近 0，不参与画面。

关键坑：**Phong 的镜面项在整片平面湖上会统一命中**（法线处处相同 ⇒ 整片湖同时进入高光），
实测把湖面冲成 #d6d7aa 的奶白。镜面必须压到近黑（`specular:0x070806`），高光交给碎光项。
另两条：① 亮度修正要在**线性空间**里估量级 —— 加 0.2 线性约等于加半屏亮度；
② 反光条不能用**绝对白**去 mix 反照率（线性 0.8 的白混 13% 就把深水抬成灰白），
必须写成按比例调制（`diffuseColor.rgb *= 1.0 + k*streak`）。

动感实测（固定相机、同一页面内相隔 1.4s 取两帧）：
**MAD 0.19 → 1.47，变化像素占比 0.1% → 17.9%，平均亮度 171.7 → 157.6**（水面由发白转为青绿）。
岸边人眼高度实测 #79a282 / #6a987c，俯视实测 #497f51（改前 #cace9e 的奶白）。

  换成纯 Phong 水 1.64ms，再去掉树冠补光 1.55ms —— 两个着色器合计约 **0.4ms（软件光栅）**，
  真实 GPU 上远小于此。draw call 188、三角面 1,444,627、dpr 2（2264×1562）与改前完全一致。
- **真因是水面动画触发的整帧重绘**。湖在视野内时，代码每 250ms 就重绘**整帧**
  （全分辨率 + 4×MSAA + 后处理）。改前水几乎不动，这 4fps 的重绘**看不出变化**；
  改后水面真的在动，4fps 的台阶就变成了肉眼可见的卡顿 —— 在弱 GPU 上，一帧要几百毫秒，
  4fps 就等于把 GPU 长期占满。
- **修法**：`createWaterClock` 间隔改为可读函数；渲染循环按**真实出帧间隔**自适应降频
  （>420ms 就把间隔拉到 gap×1.6，上限 1.5s；<330ms 逐步回到 250ms），
  交互一开始立刻恢复 250ms。`#runtime` 的 `waterIntervalMs` 可直接看到当前值。
  慢机上水面会明显变慢，但 GPU 不再被占满；快机上仍是 250ms。

教训：**「画面在动」和「看不出在动」的 GPU 成本是一样的，但只有前者会被用户感知成卡顿。**
凡是靠定时器驱动整帧重绘的效果，都要有按实际帧时的退避，不能只看 CPU 侧的 render 耗时
（`renderMs` 只有 2ms，完全反映不了 GPU 压力）。

### 修正：空闲不再出帧（11-10 22:2x）

上一版的「自适应降频」在真实显卡上不可靠：CPU 侧的起帧间隔始终是 250ms，
GPU 落后时测不出来，于是仍然持续 4fps 重绘整帧，弱机上直接把页面拖死。

现在改成 **水面只在「本来就在出帧」的时候流动**：拖动、环绕、漫游、飞行、交互后短暂窗口，
`canMoveWater()` 才为真；一停手就不再有定时器，也不再有整帧重绘。

实测（同机位、加载后 4s 起测两段 3s 窗口）：**出帧数 0 / 0**，`waterMode=still`、
`waterPending=false`、`continuous=false`。改前为空闲 4 帧/秒、`waterPending=true`。

代价：站着不动时水面是定格的。若日后要恢复常动，必须同时接受空闲时持续重绘整帧的 GPU 成本，
或在弱机自动关闭 —— 不能两全。

### 再修：软渲染直接进省电档 + 拖拽时才开始采样（11-10 22:3x）

用户在内置预览里仍报卡。补两处此前漏掉的判定：

1. **软件光栅没被识别**。预览面板/无独显环境常走 SwiftShader（`WEBGL_debug_renderer_info`
   返回 `SwiftShader` / `Basic Render`），这种环境按 60fps 跑 350 万像素 + 4×MSAA 必卡。
   新增 `gpuIsSoftware(renderer)`，命中就直接 `initialQuality → low`
   （实测：面数 1,444,627 → 280,771，dpr 2 → 1，阴影关闭）。
2. **拖拽时根本不采帧率**。`continuous` 原来只含 auto/flight/benchmark/walk，
   拖动不在内 ⇒ `frameMeter` 不采样 ⇒ 帧率看门狗永远不会降档。已加入
   `state.dragging || time < interactionUntil`；同时把 WD_N 90→60、均值 >90ms 时直接跳两档到 low。

手动兜底：URL 加 `?q=low` 会钉死省电档（`PIN_Q` 生效时看门狗不再改档）。

### 归因：水 vs 光影（11-10 22:4x）

用户要求「是水就停水，是光影就改光影」。做了同机位 A/B（SwiftShader，1692×1038 拖动模拟，100 帧）：

| 版本 | 拖动帧率 |
|---|---|
| 带新水着色器 | 3.8 fps |
| **水整体回退**（材质+贴图都回到底版） | **3.8 fps（毫无变化）** |
| 水回退 + 关后处理 `?post=0` | 4.9 fps（+29%） |
| 水回退 + 省电档自动跳过后处理 | **4.9 fps** |

结论：**水不是原因**（去掉后帧率一点没变），**光影后处理有约 29% 的实测成本**。
处理：水面整体回退到底版（不再有新着色器与新贴图）；省电档直接跳过整条后处理；
光轴采样 28 → 20、`rayWeight` 0.11 → 0.15 补偿亮度。

仍未解释的部分：软件光栅下即便 962×663 / 28 万面也只有 4.9fps，说明剩余开销是场景光栅化本身，
这部分在硬件 GPU 上不成立。若真实窗口仍卡，优先怀疑预览面板的 GPU 进程已回退到软渲染
（关掉面板重开才会恢复，刷新无效）。

### 按用户要求：光影与水面全部还原（11-10 22:4x）

用户要求「光影处理不了就先还原，换方式再修」。已把后处理完全还原：
光轴采样 28 次、`rayWeight 0.11`、`density/28`、省电档照常走后处理 —— 与改动前逐字节一致
（构建源码摘要回到 `a7fa6d8f6efd`，与「只回退水面、尚未动光影」那一刻相同）。

当前相对底版仅剩四项，都不改变画面风格：
1. 树冠透射补光（修树冠近黑）
2. 低模 `trunkLow/treeLow` 补顶点色（修省电档纯黑树）
3. 软渲染环境自动进省电档（`gpuIsSoftware`）
4. 拖动时也采样帧率（看门狗原来在拖动时不工作）+ 水面只在出帧时流动

代价：省电档恢复后处理后，软件渲染环境会重新变慢；这是还原光影的必然结果，等新方案。

## 八、2026-11-11 三项：拖拽回归 / 清澈水体 / 树木开销

### 1. 鼠标拖拽卡顿（回归修复）

- **位置**：`render()` 内 `const foreground=...,continuous=...` 与 `if(stats)`。
- **原因**：11-10 我把 `state.dragging` 加进了 `continuous`，于是帧率看门狗在**拖动过程中**开始采样，
  一旦均值 <48fps 就改 `state.moveScale`（→ `renderer.setDrawingBufferSize` 重建画布与全部后处理 RT），
  更慢时直接 `setQuality` → `setDetail` 逐个替换所有 InstancedMesh 的几何。
  两者都发生在拖动中途，表现为**每秒一次的大顿挫**，而不是持续低帧。旧版拖动时不采样，所以没有这个抖动。
- **修法**：`continuous` 恢复为原表达式（只含 auto/flight/benchmark/walk）；`if(stats)` 再加
  `!state.dragging` 守卫，保证任何降档/分辨率自适应都不会在拖动中发生。
- **效果**：拖拽链路与旧版一致；两种视角模式（拖拽 / 指针锁定）都不再被中途改档打断。

### 2. 水体更清澈

- **位置**：`waterTexture()`、`lakebedTexture()`（新增）、`materials.lakebed`、`flatShape(data.lake,.50,'lakebed')`、`createWaterMaterial()`。
- **做法**：湖底加一层真实湖床（沙砾贴图，y=.50），水面改半透明（`opacity .78`、`depthWrite:false`），
  贴图改为「中心深、环岸浅」的径向青绿；镜面压到近黑 —— **平湖上 Phong 镜面会整片命中**，不压就会冲成灰白。
- **效果**：湖面从 `#cace9e`（奶白）变为 `#71a57f`（青绿，中心深、岸边浅），能透出湖床。

### 3. 树木光影开销

- **位置**：`buildCampusScene` 里 canopy 的 `onBeforeCompile`。
- **做法**：透光补光只保留给高画质的裁切叶片 `canopy`；省电档的 `canopyLow` 是实心低模、
  整面受光，不存在叶背问题，去掉这道程序（少一个 shader program、少一条逐像素加法）。
- **说明**：树真正的成本是 alpha-test 的过度绘制，不是这一条加法；再要下降只能动叶片密度或关 alphaToCoverage，
  两者都会改观感，暂未做。

`public/map/` 里 19 个旧的模块化文件每次构建都会被 `prune` 删除，本轮删到 50 个触发
`SAFE_DELETE_BULK_CONFIRM_REQUIRED`。改为手动执行 build 链 + 回收站清理，产物与摘要一致（B-v53.1）。
另：本轮遗留 7 个本地测试服务进程（5410-5416）已全部结束。

### 追加：取消省电档（11-11 用户要求）

树木「变方块」= 降到了 `low`：`setDetail('low')` 把树冠换成实心低模（`crown(...,false)` 的二十面体团块），
且档位只降不升，一旦掉下去整局都是方块。用户要求直接去掉这个档。

改动（6 处，全部是"任何入口都不许落到 low"）：
1. `#quality` 下拉：删掉「省电」，只剩 标准 / 清晰；
2. `setQuality(name)`：入口处 `if(name==='low')name='balanced'`，兜底也改 `balanced`；
3. `initialQuality()`：最低返回 `balanced`（软渲染 / 弱设备不再直接省电）；
4. 帧率看门狗：只从 `high → balanced`，不再跳 `low`；
5. CPU 帧时兜底降档：同样只到 `balanced`；
6. `DEV_LOW` 强制档：`balanced`。

效果：树冠永远是叶片模型（面数 1,444,627），不会再出现实心低模方块。
代价：极弱设备上可能会慢，但不会突然"变样"——这是用户明确选择的取舍。

# Campus Insight · 账号与圈子

v31 首次打开提供三步指引，可点右上角“跳过引导”，之后从“使用帮助”重看。不想注册时，点“暂不登录，先体验个人测评”。跳过的是指引或账号步骤，圈子填报仍需登录；十题答案需要完整填写后才能生成报告和确认提交。

v27 同时支持“使用者独立部署”和“维护者提供公共站点”。Windows 可双击 `deploy/配置并启动.cmd`，其他系统运行 `npm run configure`；同一套程序按提示配置。完整启动、HTTPS、公开部署包下载、答卷导出和迁移步骤见随包附带的《双方案部署与交接.md》。下文继续说明账号和填报功能。

这版已经可以在本机完整试用“管理员建圈 → 邀请成员 → 在线填报 → 查看原始答卷与汇总”。以后要让不同地点、不同设备的人共同使用，再把同一套程序部署到云端。现在不需要购买服务器。

## 先理解本机和云端

| 运行方式 | 适合做什么 | 数据在哪里 |
| --- | --- | --- |
| 本机 Node 服务 | 自己体验、开发验收；关闭服务后其他人无法连接 | 本机私有数据库目录 |
| 云端 Node 服务 | 管理员和成员在各自设备使用同一个网址 | 云服务器的持久磁盘 |
| 仅上传 dist 的静态托管 | 个人测评、CSV 分析、地图 | 无账号服务，不能用于多人圈子 |

当前选择：**同一套前端与服务端，先本机运行，后续单台云服务器部署。**账号系统不是保存在浏览器里的演示数据。服务重启后，账号、圈子、答卷仍保留；更换浏览器需要重新登录。

## 1. 打开网站，注册自己的账号

第一次在 Windows 上试用：完整解压管理员部署包，打开“先看这里.html”，Windows x64即用包已自带运行工具，直接双击最外层的“开始使用.cmd”；通用包需要先安装一次Node.js 24.21或更新版本。浏览器会自动打开网站。不需要配置端口、初始化口令或数据库。

1. 在网页点“登录 / 我的圈子”，选择“注册”。
2. 想自己收集答卷，选择“创建圈子，我当管理员”。设置账号、6～12位密码，圈子名称选填。点击“注册并创建我的圈子”即可。
3. 想填写别人的圈子，选择“使用邀请，加入已有圈子”，粘贴邀请码。直接打开邀请链接时会自动带入。
4. 已有账号直接登录，不需要重新注册。每个人都可以创建自己的圈子，管理员权限只限于自己创建的圈子。

下次使用，仍双击“开始使用”，登录原账号即可。保留整个私有数据文件夹，账号和答卷会保留。无需查找 `setup-key.txt`，新版本不再生成用户开通口令。

新密码和修改密码均为6～12位，允许纯数字。原来设置的长密码仍可登录。请自行保存账号和密码，当前没有邮件找回功能。

源码开发者仍可使用 `npm ci`、`npm run build`、`npm start`。已经配置正式网站的目录，请使用原来的服务启动方式，便捷入口不会改写正式配置。

## 2. 管理员怎么使用

1. 登录，选择“我要收集答卷”，给圈子起名后点击“创建圈子，我来收集”。新建后会定位到圈子名称，请先确认名称。
2. 点“下一步：邀请成员”，在“邀请成员”设置可加入人数（1–100）和有效期（1、3或7天），点击“① 生成邀请”。默认30人、3天，可自行调整。
3. 点“② 复制邀请链接”，再打开自己的聊天工具粘贴发送。自动复制失败时，可展开链接框手动复制。邀请码只在生成时显示原码；之后可查看使用次数、到期时间并撤销，不能找回原码。本机网址暂时只能本机使用，异地成员需要公开可访问的同一站点网址。
4. 成员提交后，选中圈子并点“查看最新数据”。“成员与答卷”显示已交、未交、提交时间及每人的最新原始答案。计数包含管理员，管理员可以点击工作台上的“我也填写一份”，也可以从首页答题后，在档案页直接选择本圈提交。
5. 点击“查看圈子汇总”，看到当前题库版本答卷的逐题统计与画像。汇总使用每人的最新一份答卷，不重复统计重交的人；没有答卷时按钮禁用。

每个圈子上限 200 人，每个账号最多创建 10 个圈子、加入 20 个圈子。当前每个圈子只有创建者具备管理员权限；邀请码仅授予成员权限。每个账号都可以另建自己的圈子，但不能因此查看别人的圈子。

移除成员会删除其在本圈的成员关系及答卷，不能在产品中恢复。操作位于折叠确认区，谨慎点击。对方的账号及其他圈子不受影响。

## 3. 成员怎么使用

1. 打开同一个站点，点击“登录 / 我的圈子”，新用户选择“注册”，填写账号、6～12位密码和管理员提供的邀请码；显示名称选填。邀请链接会自动带入邀请码。
2. 已有账号直接登录，邀请链接会带入加入入口；也可在“我要填报 · 加入圈子”输入邀请码，不用重复注册。
3. 选中圈子，点“开始填写”。每题选一个答案，再点“下一题”，选错可以回上一题；十题都要填写。“稍后填写，回到圈子”可保留当前标签页草稿，下次点“继续填写”。不同圈子、不同账号的草稿分开保存，退出或切换账号后清除旧账号的圈子草稿。
4. 答完点“查看我的报告”，在档案页直接点击“提交到我的圈子”。多个圈子时先选择一个，核对圈子、账号与十题原始答案，阅读共享范围，勾选同意后再点“③ 确认提交到圈子”。管理员自己也使用这个入口。服务器确认保存后才显示成功。也可以“稍后提交”，保留草稿回圈子，以后继续。
5. 返回圈子，可查看自己的最新答卷和提交时间，也可重新填报或撤回。重交替换最新答卷，界面保留提交次数，不提供历史版本列表。

如果网络失败，**先回圈子刷新核对是否已经保存**，再决定重试；连接中断时浏览器可能没收到服务器成功响应。不要只根据按钮是否变色判断。

其他成员不能查看你的答卷。管理员可查看你主动提交的原始答案、显示名称与提交时间。撤回后，答卷会从当前圈子列表和汇总移除，但管理员已另行保存的副本及服务备份无法一并撤回。退出登录不会删除已经提交的答卷。

请妥善保存账号密码；可在“账号安全”中修改密码，修改后其他设备旧登录立即失效。目前不提供邮件找回、短信验证码、管理员交接或多管理员协作。

## 4. 数据和备份

私有数据为 `.campus-data/campus.sqlite` 及运行中的 WAL/SHM 文件。不要放入 `public`、`dist`、Git 或网站文件下载目录。交付包、Docker 构建上下文和前端构建会排除这些数据；更新程序时保留现有私有目录，不要用空目录覆盖。

在程序目录运行：

```powershell
npm run accounts:backup
```

会在私有数据目录的 `backups` 子目录生成 SQLite 一致性快照，可在服务运行时备份。备份含账号派生密码和原始答卷，务必存放在有访问控制的私有磁盘，定期复制到另一处私有存储。不要直接复制正在写入的单个 `.sqlite` 文件代替此命令。

恢复时先停止服务，保留当前数据库及其 `-wal`、`-shm` 文件到一个私有归档目录，再把备份复制为数据目录中的 `campus.sqlite`，确认旧 WAL/SHM 不在原位置后重新启动。恢复会把答卷、成员关系、密码和会话一起回退到备份时间；先在隔离实例验证备份，正式恢复前做好当前备份。

个人测评、上传 CSV 和统计仍在浏览器计算；只有主动确认提交圈子才保存原始答卷。配置在线模型后，个人报告会发送所选答案与报告摘要生成解读，圈子解读只发送汇总统计，不发成员名单、账号、邀请码或逐人答卷。基准为 2000 条模拟记录，画像不用于心理评估或成员考核。

## 5. 以后怎样上线（还没有执行）

到准备给成员使用时，我们再一起完成选平台和部署。需要的资源是：**运行 Node 的服务、一块不会随重启消失的磁盘、HTTPS 网址及备份位置**。不需要给每个成员买服务器，也不需要每人安装程序。

部署时由同一服务提供网页和 `/api/campus/`、`/api/llm/`。设置环境变量：

```text
HOST=0.0.0.0
PORT=5191
CAMPUS_DATA_DIR=/data/campus
APP_ORIGIN=https://你的正式域名
```

`APP_ORIGIN` 必须是完整 HTTPS 来源，不能带路径或末尾斜杠。非本机访问而未配置它时，账号接口会拒绝服务。HTTPS 下使用 Secure、HttpOnly、SameSite 的主机专属会话 cookie；反向代理须保留 Origin，支持 AI 流式响应。不要把内部端口直接当作正式 HTTP 站点给大家使用。

项目附带 Dockerfile 作为可选部署入口；正式运行时将 `/data` 挂载为私有持久卷，并设置 `APP_ORIGIN`。容器构建与公网部署尚未在本机验收。当前 SQLite 方案适用于一个服务实例和小圈子，不要把多台服务各自连到不同的本地数据库；以后需要横向扩展时再迁移到共享数据库。

更新服务请继续挂载原来的数据卷；若云平台会在重启或重新部署时清空磁盘，必须先配置持久卷，不能直接上线。模型密钥仅在服务器环境变量或私有密钥文件中配置，不能发送到聊天或写进前端。

实现依据：[Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)、[OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。本版使用原生 scrypt、服务端会话和逐圈权限检查，没有浏览器本地假账号。

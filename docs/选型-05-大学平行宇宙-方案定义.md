## 一、方案原文（本人提出，未删改）

> 核心思路是：**让评委不做观众，做数据源。** 不用他有任何账号，只需要在现场回答几个好玩的、有共鸣的简单问题，系统就生成一份专属的「大学时代数据叙事报告」。整个过程大约 30 秒，结果因人而异，且一定逗乐评委。
>
> 我称之为：**「你的大学平行宇宙」—— 个人青春行为图谱生成器。**

**演示流程**：请评委走上台 → 大屏逐个显示问题，评委选一个 → 系统记录 → 答完立刻生成专属报告。

**问题示例**（本人设计）

| 问题 | 选项 |
|---|---|
| 大学时，你深夜最常出没在哪个角落？ | 宿舍床上 / 图书馆自习室 / 操场跑道 / 食堂窗口 / 网吧 |
| 期末复习周，你的生存方式？ | 死磕课本 / 刷往年题 / 组团开黑边复习 / 临时抱佛脚 |
| 你大学吃宵夜的频率？ | 天天吃 / 一周三五次 / 偶尔 / 从不 |
| 如果大学能重选一次，你会加入什么社团？ | 乐队 / 辩论队 / 电竞社 / 志愿者协会 / 摄影社 |

**输出五件套**

1. **雷达图** —— 大学生活者画像：学术力 / 社交力 / 运动力 / 美食力 / 佛系指数
2. **时间轴** —— 模拟四年心情起伏线（「大一：以食堂为中心展开社交；大二：在宿舍和图书馆之间反复横跳…」）
3. **环形图** —— 时间去哪了：学习 / 娱乐 / 社交 / 干饭 / 睡觉 比例
4. **人群冷知识** —— 「比你更频繁吃宵夜的人只有 12%，你是深夜食堂的神秘部员」
5. **大模型个性化总结** —— 「王老师，你是一个『学术与干饭并重』的选手……你的青春关键词是：热气腾腾」

**本人陈述的核心竞争力**

> 结果属于评委本人。人类对自己的好奇心远大于对抽象数据的好奇。评委输入账号时，他看到的是「别人的数据」；但他亲手做出选择时，他看到的是「我自己」。这个「哦，这就是我！」的瞬间，就是全场最亮的那一刻。

## 二、为什么这个方案成立（检索依据）

### 2.1 它自己修掉了候选 ⑥ 的硬伤

候选 ⑥「公开 API 实时画像」的死穴是：**评委必须有对应平台的账号**。现场若无人有账号，演示当场冷场。

本人方案把「评委需要准备的东西」降到 **零** —— 不需要账号、不需要数据、不需要安装任何东西，只需要**回答问题**。而「回答问题」比「输入账号」的参与门槛更低、心理负担更小。

### 2.2 命中了已被验证的核心机制

Pudding Cup 2025 的获奖作品里，有一件是**作者分析自己 100 天的填字游戏记录**。它拿奖不是因为技术，是因为**分析对象是「我」**。

本人方案把这个机制放大了：**不是让作者看见自己，而是让评委看见自己。** 这个「我」的强度比前者高一个量级。

### 2.3 「人群对比」补上了「垂直社区」的定位缺口

「比你更频繁吃宵夜的人只有 12%」这一句，让产品从「一个人的测试」变成「**一个社区里的位置**」。方向 6 要求的「垂直社区」属性，靠这句话立住了。

## 三、⚠️ 三处必须先焊死的接口

### 接口一：五样输出，靠四五个问题怎么算出来？

**这是最要命的一处。**

| 输出 | 由输入直接推导的可能性 |
|---|---|
| 雷达图（5 维度） | ✅ 可以直接映射 |
| 环形图（学习/娱乐/社交/干饭/睡觉占比） | ⚠️ 靠「宵夜频率」推不出「干饭占多少时间」 |
| 时间轴（四年心情曲线） | ⚠️ **四五个离散选项，推不出四年连续曲线** |
| 人群冷知识 | ⚠️ 依赖外部基准数据（见接口二） |
| AI 总结 | ✅ 有摘要就能写 |

**核心矛盾：输出维度 > 输入维度。**

中间那段「算法演绎」如果设计不好，会出现最坏情况：**不同的人答了不同的题，生成的东西看起来却差不多** —— 那「这就是我」的效应当场崩塌。

**两条解法路径（待本人选）**

| 路径 | 做法 | 代价 |
|---|---|---|
| **A · 加宽输入** | 问题数从 5 提到 8~10 个，提高分辨率 | 时间从 30 秒拉长到 ~60 秒；评委耐心下降 |
| **B · 建立映射矩阵** | 设计「选项 → 属性」对照表，让**每个选项同时影响多个输出维度**（例：选「图书馆自习室」→ 学术力+、社交力−、时间分配里学习占比+） | 前期需要设计一张完整的映射表；但问题数不必增加，且结果分化度更高 |

> 💡 路径 B 是这类产品的真正工作量所在，也是「方法创新性」评审维度最容易拿分的地方 —— 因为它是**可解释的设计**，而不是随手写的规则。
>
> 两者也可叠加（如 6 题 + 映射矩阵）。

---

### 接口二：「比你更频繁吃宵夜的人只有 12%」——这个 12% 从哪来？

如果百分比是随口编的，评委追问一句就露馅。

**但这恰好是一个机会** —— 把基准数据做成一份**真实存在的 CSV**：

- 「2000 名大学生的问卷结果」作为数据源
- 方向 6 的「数据源（CSV）→ 图表」链路**由此获得正式依据**（不再只是几个选项）
- 「人群对比」有真实出处，可当场亮出来
- 同时保住了此前已写好的数据层（`parseCsv` / `validate` / `cleanData`）**100% 复用**

⚠️ 但这份基准数据必须**真的造出来且逻辑自洽**（与之前「学习记录」同样的要求），并在 README 声明为模拟生成。

> 💡 附带好处：有了基准数据集，产品就可以展示「**你这个类型的人在全人群中排第几**」这类真正的数据结论，而不只是单点百分比。

---

### 接口三：评委在现场吗？

「请评委走上台」这个设计在**现场路演**是满分。但如果省赛是**线上材料评审**，评委不会上台，只能看视频 —— **而视频里是别人在点选项。**

**「这就是我」的效应，在视频里会消失。**

**推论：本方案几乎强制要求「线上可访问的链接」。**

上一轮讨论的「要不要部署」，在这里从加分项变成了**必要条件**：

| | 无线上链接 | 有线上链接 |
|---|---|---|
| 现场路演 | ✅ 可用 | ✅ 可用 |
| 线上材料评审 | ❌ 核心机制失效 | ✅ 评委自己答、自己看结果 |

**实现要点**：纯静态站点即可部署（无后端、无数据库）。大模型若未配置密钥，降级为内置模板文案 —— 但即便降级，**「自己答完看到自己的结果」这个机制仍然完整**。

## 四、还有一个取舍，需要本人判断

这个产品本质上更接近「**人格测试 / 娱乐产品**」，而不是「数据分析工具」。

评审权重中 **「解题有效性与实用价值」占 25%**，纯娱乐向在这一项会吃亏。

**一条可能的出路（是出路，不是结论）：让产品有两个入口**

| 入口 | 做什么 | 负责哪件事 |
|---|---|---|
| **快入口** | 回答 5 题 → 30 秒出报告 | 负责「亮」—— 评委现场玩 |
| **真入口** | 上传真实的校园数据文件 | 负责「有用」—— 接上已写好的数据层 |

这样「平行宇宙」的设定反而更完整：**快入口是想象，真入口是现实。**

代价是开发量增加。**加不加这一层，本人定。**

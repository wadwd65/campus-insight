# v28 用户部署体验评估

评估日期：2026-10-22。结论：**当前本机流程的方便性为 6.5/10；可以完成小圈子收答卷，但还不能称为普通人开箱即用的部署产品。** 原 v27 包的 Windows 启动存在阻断，本轮修正后继续完成实测。

## 方法与范围

从已交付的 v27 ZIP 解压到新的中文、带空格目录，实际执行 Windows `.cmd`，逐项回答配置问题，再用浏览器界面走管理员和成员操作。全部使用新建虚拟账号和十题合成答案，独立端口 5195/5196，没有动原站点数据库、模型密钥或 3D。

这是**一个熟悉产品的执行者进行的引导式模拟**，不是普通用户盲测。分数是按公开标准给出的判断，不是用户调查统计。不将工具调用耗时当作人类完成时间，也不声称测得真实新手成功率。

本机已安装 Node.js 24.21.0；本轮未从零安装 Node。第二个站点选择“公共站点”用途，但仍在本机运行，不能据此声称互联网发布、HTTPS、容器或异地访问已成功。

## 实际发生的阻断

原 ZIP 中两个 Windows CMD 入口只有 LF。真实 `cmd.exe` 执行“配置并启动”时，出现命令无法识别，接着误报需要安装 Node；同机 `where node` 已找到 Node。原文件无 CRLF；只转换为 CRLF 后，同一路径立即进入配置并正常启动。因此原包的 Windows 首次部署验收为**失败**，此前自动检查漏掉了这个入口。

已修正工作树文件，Git 对 CMD 强制 CRLF，打包器也规范换行。新增真实 cmd.exe 在中文带空格目录回答七个问题、最后取消且不写配置的回归；修正后的“直接启动”脚本也在实际生产包中启动成功。用户应使用 v28 修正包。

## 方便性评分

评分锚点：9–10 分为普通使用者基本无需技术解释即可完成；7–8 分为清晰引导下可完成，少量摩擦；5–6 分为可用但需要终端、配置知识或人工帮助；1–4 分为频繁受阻或关键任务难以完成。首次部署按**修正后**流程评分；原包阻断另列失败，不能被平均分掩盖。

| 维度 | 权重 | 分数 | 主要依据 |
| --- | --- | --- | --- |
| 首次自部署与初始化 | 30% | 5/10 | 无 npm 运行依赖较好，但要先装 Node、回答七个终端问题、理解监听/端口/私有目录，手动打开网页、找文件口令 |
| 成员注册与填报 | 25% | 7/10 | 答题和提交范围清楚；邀请仍靠长码，注册后不自动进入邀请圈子，额外选圈且空态文案误导 |
| 管理员日常收答卷 | 25% | 8/10 | 原答案、时间、汇总、导出都能直接拿到，免文件收集；页面较长，需要手动刷新 |
| 备份、恢复与交接 | 20% | 6/10 | 真实恢复保留关系和密码，拒绝覆盖较稳妥；仍需终端、文件路径和恢复顺序知识 |

这不是网站美术、3D 精细度或安全审计评分。核心小圈子任务已经跑通；“作者不长期维护，普通管理员自己轻松接手”的目标仍只部分实现。拥有部署包可以继续运行，不等于不需要任何运行维护。

## 仍然明显的体验问题

1. 首次配置偏技术化。大多数人只想“双击→打开网页→建号”，不理解监听、反向代理、容器与私有数据目录。
2. 初始化需要在终端、文件管理器、网页间切换。出错时的说明应直接指向实际问题，不能误报 Node 未安装。
3. 邀请不是一个可直接打开并带入上下文的链接。成员注册后显示“选择一个圈子，开始一起记录 / 创建后你就是管理员”，对已加入的普通成员不准确；提交后返回也会丢失当前圈子选择。
4. 刷新网页会再次出现入场动画并回到首页，对正在管理圈子的人增加步骤。
5. 管理员界面先展示自己的填报与邀请，成员收集结果在页面下方；用户多时的查找与筛选体验尚未实测。
6. 备份仍需主动运行命令、另存私有文件；没有面向普通管理员的引导式恢复和定期备份入口。
7. 公网部署仍依赖服务器、域名、HTTPS 和持久存储。只选择“公共站点”不会替用户完成这些工作。

这些问题作为评估保留，本轮只修复阻断部署的 CMD 问题，没有先把所有摩擦改掉再给原流程高分。

## 建议的下一轮顺序

先做网页首配和打开浏览器引导，再做邀请链接、加入后自动进入圈子及准确空态，随后把管理员收集概况提前、补备份引导。之后选定一个实际托管平台，完成域名、HTTPS、持久磁盘、重启和跨设备访问验收，再招募不熟悉代码的使用者独立部署并记录卡点。

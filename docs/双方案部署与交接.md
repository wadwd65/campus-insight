# 两种部署方式，共用一个管理员包

你可以直接使用维护者提供的网站，也可以保存部署包，自己运行。两种方式共用同一份程序、问卷和权限规则，不需要等待原公共站点继续维护。独立部署后的数据由部署者保管；独立站点之间不会自动同步账号或答卷。

## 第一次在自己的 Windows 电脑上试

先打开包内的“先看这里.html”，其中有逐步说明。日常使用只需：

1. 右键压缩包，选择“全部解压缩”。
2. Windows x64即用包无需安装运行工具。通用包需要安装一次Node.js 24.21或更新版本，已经装好可以跳过。
3. 双击最外层的“开始使用.cmd”，等浏览器自动打开。
4. 网页上点“注册”，选择“创建圈子，我当管理员”，设置自己的账号和6～12位密码。
5. 下次仍双击同一个“开始使用”，登录原账号。不用重新配置或注册。

不再需要初始化口令。答完问卷，在我的档案中点“提交到我的圈子”，核对共享范围后提交。自己的填报入口也直接放在管理员工作台。

启动窗口请保持打开，停止时按 Ctrl+C。账号和答卷默认保存在原文件夹里的 `.campus-data`，更新程序前请先备份并保留数据。双击“备份我的数据”生成备份，双击“打开数据文件夹”查看实际位置。

## 让其他人从手机或电脑访问

本机的 `127.0.0.1` 只代表这台电脑。想让其他人填写，需要服务器和正式 HTTPS 网址。成员只需要浏览器，不需要安装程序。

不熟悉服务器时，把完整部署包和“给部署者的交接.md”交给帮助部署的人。已有服务器的使用者可以打开 `deploy/配置并启动.cmd` 进行正式配置。这个工具是进阶入口，本机试用不需要先填写它。

服务器需要持续运行并保留私有数据。具体的部署、重启、备份恢复由运行者负责。

## 维护者提供公共网站

使用同一个包，配置时选择“公共站点”。维护者运行一套服务，多个管理员各自建圈，成员通过相同网址与邀请码进入。这个选择用于标注站点用途，不会放宽权限：创建者仍只管理自己的圈子，其他圈子的管理员没有跨圈访问权。

任何人都可以注册并创建自己的圈子，无需原管理员邀请。加入他人的圈子仍须邀请，邀请本身只授予成员权限。维护者拥有服务器访问权，应妥善保管数据库，但网站没有“任意读取所有圈子”的后台接口。

使用带持久磁盘的 Node 托管时，配置：

```text
CAMPUS_DEPLOYMENT=shared
CAMPUS_SITE_NAME=你的公共站点名称
APP_ORIGIN=https://你的正式域名
HOST=0.0.0.0
PORT=5191
CAMPUS_DATA_DIR=/你的私有持久磁盘/campus
```

这些设置可由配置工具写入 `.env.local`，进程环境变量优先。模型服务是可选配置；没有模型仍可完成统计和本地解读。不要把密钥写进前端或发送到聊天。

## 可选：自有服务器用 Docker Compose 与 HTTPS

以下命令面向已安装 Docker Compose、拥有正式域名和服务器访问权限的部署者。此模板使用部署包中的已构建网页，无需再下载前端 npm 依赖。

1. 在解压目录运行配置工具，选择独立部署或公共站点，并填入不带路径、端口和末尾斜杠的 HTTPS 正式域名。配置会写入 `CAMPUS_DOMAIN`。
2. 将域名的 DNS 指向服务器，确保服务器的 80、443 端口可供 HTTPS 服务使用。部署前确认该域名确实由你管理。
3. 在解压目录运行：

```sh
docker compose --env-file .env.local -f deploy/compose.yaml up -d --build
```

模板由 Caddy 提供 HTTPS 并转发到内部 Node 服务，Node 端口不直接映射到公网。数据库保存在 `campus-data` 命名卷，证书与配置也使用持久卷。不要运行带 `-v` 的卷删除命令；重新部署时保留同一套命名卷和项目目录名称，避免误连到空数据库。

打开正式网址后直接注册，自设账号和密码并创建圈子，不需要读取服务器口令。

模型密钥文件如果是宿主机路径，容器不能直接读取；需另行挂载为容器内私有文件，或用服务端环境变量配置密钥。不要因为模型未配置而公开宿主机目录。

部署依赖域名、端口、网络和证书服务。模板不表示公网已部署成功，也不承诺在每个网络均可访问。若本机没有 Docker，仍可使用原生 Node 包与托管平台提供的 HTTPS。

## 向其他人提供独立部署包

网站的“我的圈子”中提供“使用现有网站，或自己部署一份”说明。维护者可以把**校验过且不含凭据的通用部署 ZIP**复制到解压目录的：

```text
release-download/campus-insight-admin.zip
```

网页会自动显示“下载管理员部署包”，无需重新构建。Compose 模板已把这个目录只读挂载给应用。此文件是公开下载，不能放数据库备份、环境文件、初始化口令、模型密钥或用户数据。通用部署包不会把这个下载目录再嵌入自身，避免递归打包。

如果未来停用公共站点，请在停用前通知使用者保存部署包和自己的数据；程序不会自动替你通知成员，也不会在站点停止后继续提供下载。保存到本地的完整部署包可独立运行。

## 数据带走与换服务器

**成员**可在自己的圈子详情导出已交答卷。**圈子管理员**可在“成员与答卷”展开“导出本圈原始答卷”，保存显示名称、十题答案、提交时间和次数。CSV 使用每人当前题库版本的最新一份答卷，不包含未提交成员、账号密码或邀请码。

CSV 可在自己部署的网站“导入已有 CSV”中继续做统计；导入统计不会创建在线账号或自动归属答卷。迁移后如要继续在线填报，新站点需重新邀请成员注册。旧版题库答卷不会混入当前题库导出，请在更换题库前留存相应版本的数据和程序。

**整站接任者**需要保留账号、圈子与在线填报关系时，由原站点维护者执行一致性备份：

```sh
npm run accounts:backup
```

备份位于私有数据目录的 `backups` 子目录。Docker 中可运行 `docker compose --env-file .env.local -f deploy/compose.yaml exec app node scripts/backup-accounts.mjs`，再通过服务器的私有文件传输方式取走备份；不要公开下载它。

接任者在新服务器解压同版本管理员包，先配置一个**新的空私有数据目录**，保持服务未启动，然后运行：

```sh
npm run accounts:restore -- /私有路径/备份.sqlite
npm start
```

恢复工具检查备份完整性与格式，保留账号密码、圈子和原始答卷，清除旧会话、撤销旧邀请码。用户重新登录，管理员生成新邀请。工具拒绝覆盖现有数据库；如果目标已有数据，请换新的空目录，不要删除现有数据来尝试。

只迁移程序文件不会迁移数据。交接时应分别保存：管理员部署 ZIP、私有数据库备份、域名及服务器访问权、私有模型配置。公共站点维护者无需向普通成员提供整站数据库，因为它包含其他圈子的私人答卷。

官方参考：[Docker Compose 环境变量](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)、[Caddy 自动 HTTPS 与域名条件](https://caddyserver.com/docs/automatic-https)、[Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)。

# 发布验收

适用于现有Node主站和站内自包含3D入口。3D美术与功能的开发记录单独保存在《3D地图开发日志》中。

## 构建并保存依据

在项目根目录运行 `npm ci`、`npm run check`。全部通过后使用这一份 `dist/` 发布，生产启动命令为 `npm start`。

使用Node.js 24.21.0或更高版本，并记录实际Node/npm版本与执行宿主。其他版本某些脚本能通过，不等于完整支持。

如果执行宿主出现 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`，应停止该次检查并保存失败日志，记录为“该宿主下完整检查被阻断”。不要改为忽略清理错误、分批绕过限额，或把分项通过记作完整检查通过。此前某次完整运行通过的记录仍然有效，但不能保证不同宿主、权限和运行条件下均可复现。需要在允许正常构建清理的执行环境中重新完整验证，或按宿主提供的正常授权方式处理。

构建后的 `dist/build-edition.json` 自动记录版本、构建时间、基准提交、源码摘要及首页/JS/CSS/实际3D入口文件摘要。源码摘要覆盖 `src/`、`server/`、`public/`、`scripts/`、`map-src/web/`，以及地图布局、建筑参考、Three.js构建输入、包清单、Vite配置与HTML入口，不含文档、私有配置或桌面外部工作副本。`sourceDirty: true` 表示构建时相关源码有未提交修改，此时提交SHA仅代表基准，摘要用于辨识这次所覆盖的实际内容。无Git的源代码包仍可记录摘要。不要把它改成“干净提交”来掩盖实际状态。

平台如果自行重新构建，资源文件名可以变化。应保存平台本次产生的构建标识，再用同一产物验收。不同构建的文件摘要可以不同，不能仅凭文件名判定功能新旧。

## 检查线上资源

运行 `npm run verify:live -- https://你的网站`。命令只读访问网站，先比较版本和源码摘要，再按线上本次构建清单核对实际首页、全部JS/CSS和3D入口。主站更新而地图仍旧、地图404或内容摘要不符，都必须失败。

平台重新构建后，资源文件名允许变化，只要源码摘要一致、实际首页与它引用的资源均符合线上本次清单，就可通过资源核验。源码指纹不匹配时先查明覆盖范围、输入或构建过程，不能单独据此断言某个运行功能缺失。

## 真实浏览器走完操作

- 新访客跳过动画，能从首页找到十题主入口；无账号也能完成十题。
- 报告里看到本人作答对应的个人解读、五维图表、时间分配和“下一步”建议；改答案后结果真实更新。
- 先打开48人合成示例，再答十题，返回后出现个人比较，随后可进入完整档案；来源仍明确为合成数据。
- 暂停、返回、恢复档案均可使用；存储被禁用时，当次计算仍能完成，并如实说明不能恢复。
- 校园一天产生可核对的问卷建议，原答案优先；没有选择的信息保持待答。
- 在独立验收圈子中，管理员和成员分别登录、填报、确认提交；管理员看到本圈最新答卷，普通成员不能读取他人答卷。使用测试数据，不覆盖生产成员的数据。
- 在手机窄屏与电脑上检查主按钮、表单、图表和返回入口，确认无水平遮挡。

记录“实际执行”和“未验证”的项。资源检查与React DOM测试都不能代替这一步。

## 代理和数据盘

`CAMPUS_TRUSTED_PROXIES` 接受逗号分隔的代理IP/CIDR，只填写平台确认的代理来源范围。空值时忽略 `X-Forwarded-For`；全网网段 `/0` 会拒绝启动。

同机反代示例：`CAMPUS_TRUSTED_PROXIES=127.0.0.1,::1`。Docker、WorkBuddy或其他云平台必须按实际网关配置，不能照抄同机示例。服务端从右向左遍历转发链，遇到首个非可信地址即停止。已登录用户的一般请求按用户区分，登录、注册和创建账号仍保留限额。

先用隔离服务验证不同来源不互相误拦、同一来源仍受限，再重启正式服务。错误配置不能靠放开所有转发头解决。

确认 `CAMPUS_DATA_DIR` 在持久私有磁盘。更新前备份，重启后使用测试账号验证圈子和答卷仍在。不要将备份放进 `public/`、`dist/` 或公开下载目录。

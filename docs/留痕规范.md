# 留痕规范（三件套）

> 本规范 2026-09-14 定稿，全程不再变动。
> 赛事「过程可复现性与演进链路」占 25%，这一节的执行程度直接决定那一栏的得分。
> 晚一天开始留痕，就少一天记录，**这部分无法事后补做**。

---

## 一、Git 提交信息格式

```
<类型>: <一句话说明>
```

类型只有 5 个，不许自创：

| 类型 | 什么时候用 |
|---|---|
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `refactor` | 调整代码结构，功能不变 |
| `docs` | 文档、README、Prompt 记录 |
| `chore` | 依赖、配置、脚手架 |

示例：

```
feat: 支持导入数据并解析为表格
fix: 修复空数据时页面不显示提示的问题
docs: prompt-003 归档（数据解析失败的三次修正）
```

硬性要求：

- **一次提交只做一件事**，对应一次与 AI 的对话，或一个功能模块
- 说明用中文
- **禁止一次性提交**。绝不允许出现「initial commit 里包含全部功能」的情况，赛事原文点名禁止

---

## 二、Prompt 编号规则

- 存放位置：仓库内 `prompts/` 目录
- 命名格式：`prompt-001-<短标题>.md`，三位数递增，**不跳号、不回填**
- 只有「产生了实际代码变更」的对话才编号，闲聊不编号

每个 Prompt 文件固定写四段：

```md
## 1. 我的提问
（原话照抄，一个字都不改写）

## 2. AI 的回复要点
（不必全文，抓关键结论和它给了什么代码）

## 3. 哪里不对 / 我实际需要什么
（描述偏差：哪个页面、什么操作、期望什么、实际什么）

## 4. 追问与最终结果
（怎么把 AI 引导到正确方向的，最后成了没有）
```

赛事硬性要求：**至少 3 条完整的「提问 → 偏差 → 修正 → 收敛」链条**。

编号会一直增长，所以第 3 与第 4 段要写实。AI 一次就对的部分不用记，记的是**它错了、你怎么纠的**。

## 三、目录约定

```
campus-insight/
├── prompts/             与 AI 的对话记录，一个文件对应一次代码变更
├── public/data/         示例数据（CSV），评委复现时直接可用
├── docs/                规范与文档
├── src/                 源码
│   ├── components/      界面零件
│   ├── lib/             数据计算、接口封装等纯逻辑
│   └── App.jsx
├── README.md            含「10 分钟极速复现指南」
└── .gitignore
```

规则：

- `prompts/` 与 `public/data/` **随代码一起提交**，不得写进 `.gitignore`
- `public/data/` 里的示例数据必须真实可用 —— 评委 clone 下来点一下就能出图，不用自己找数据
- `src/lib/` 放纯逻辑（数据处理、接口封装），不掺界面代码。评委看架构就是从这一层看

---

## 四、每次提交前的三个自问

1. 这次提交对应哪次与 AI 的对话？那次对话记进 `prompts/` 了吗？
2. 提交信息里的类型选对了吗？这次改动是不是只做了一件事？
3. 如果是新功能：README 里对应的功能勾选框更新了吗？

## 一、为什么翻掉这个方向（留痕，评审要看）

本人原话：

> 「就是关于这个你做那个学习时间的什么东西，实际上做起来没啥意思。并且没有什么竞争力，感觉，别人一看就没有什么亮眼的，我们要做出一些看起来就有点东西，我们这个论题一点亮点都没有。」

**这不是情绪化推翻，是一个可陈述的产品判断。** 拆开看：

| 问题 | 具体表现 |
|---|---|
| 形态是标准答案 | 「CSV → 图表 → AI 写解读」是方向 6 的原文描述，**每一支队伍都会这么搭**，评委看第十个时不会有第二次惊讶 |
| 结论不反直觉 | 「你数学花时间最多、正确率最低」—— 用户自己也算得出来，不需要产品告诉他 |
| 单向流程，没有留人机制 | 上传 → 看图 → 读一段文字 → 关掉。没有第二次打开的理由 |
| 数据对象无情绪 | 学习时长是中性数字，不产生任何有张力的叙事 |

**关键结论：问题不在「做得不好」，在「这个组合的上限本来就低」。** 换配色、换文案救不了。

---

## 二、亮点的两个来源（判断框架）

一个作品「一眼看上去有东西」，只可能来自两个正交维度上的提升：

| 维度 | 含义 | 低 → 高 |
|---|---|---|
| **数据对象** | 数据本身有没有戏剧性、有没有可被推翻的假设 | 中性记录 → 带冲突/有情绪的数据 |
| **交互机制** | 用户是「看一眼」还是「必须动手」 | 静态展示 → 追问 / 回放 / 可验证 |

**当前产品站在最差的位置：中性数据 × 静态展示。** 两个维度都还有很大空间，换掉任意一维都能立刻改善，两维都换才是「一眼有东西」。

## 四、可选落点（并列，未选定）

### 落点甲 · 换数据对象：游戏行为画像

- **数据**：战斗记录 / 抽卡记录 / 在线时段（本人正在玩《异环》，本身就是用户）
- **戏剧性来源**：游戏数据天然带冲突与情绪，结论可以很「刺」
- **契合度**：方向 6 原文即「校园 / **垂直社区**」，游戏社区是标准垂直社区
- **风险**：无真实数据可导出，需人工构造；构造游戏数据比构造学习数据更容易自洽、也更有意思

### 落点乙 · 换数据对象：公开 API 实时画像

- **数据**：接真实公开 API（如 GitHub 公开提交数据），而非内置 CSV
- **亮点**：**评委可以现场输入自己的账号，30 秒后看到自己的画像** —— 可验证、可交互、有惊喜，记忆点极强
- **契合度**：方向 6 原文明确允许「CSV / JSON **或公开 API**」
- **风险**：依赖外部服务可用性；需确认接口跨域与限流

### 落点丙 · 保留数据对象，换交互机制

- **机制**：把「AI 写一段总结」升级为 **AI 先反问 → 用户回答 → AI 再下诊断**；或做成**可拖动时间轴回放**整个周期
- **亮点**：从「看数据」变成「和对自己提问的系统对话」，数据 + 人的回答才构成完整证据
- **风险**：内核仍是中性数据，仅靠机制拉升可能不够

### 落点丁 · 两维都换

- 换数据对象 **且** 换交互机制，是上限最高的组合，也是开发量最大的组合。

| 项 | 口径 |
|---|---|
| 对比度 | WCAG 2.1 相对亮度公式；正文（<18px 或非粗体）需 ≥ 4.5，大字（≥18px 或 ≥14px 粗体）需 ≥ 3.0 |

## 1. 根因诊断

**一句话**：项目里存在 **5 份各写各的颜色定义**，但没有一条「哪个底色用哪套色」的规则，
于是**为深色终端设计的琥珀/青/暗灰被直接铺到了浅色内容区**，同时 Tailwind 默认色板
（`slate-50` / `gray-200/500/800` / `indigo-600`）从未被替换 —— 两者叠加造成全站系统性对比度失败。

### 1.1 五份颜色定义（无单一真源）

| # | 位置 | 内容 | 状态 |
|---|---|---|---|
| 1 | `src/index.css:4-14` `:root` | `--ink:#1f2937` `--ink-soft:#6b7280` `--line:#e5e7eb` `--surface:#fff` `--canvas:#f8fafc` `--brand:#4f46e5` | **全是 Tailwind 默认值** |
| 2 | `src/index.css:79-89` `.term-canvas` | `--term-bg/-panel/-line/-ink/-ink-soft/-amber/-cyan` | `--term-amber` `--term-cyan` **零引用（死代码）** |
| 3 | `src/lib/theme.js:21-34` | `BRAND:#4F46E5` `INK:#1f2937` `INK_SOFT:#6b7280` `LINE:#e5e7eb` + `PALETTE` | 与 #1 重复 |
| 4 | `src/lib/surface.js:89-92` | `TERM_INK = { cyan:#4fa8d8, amber:#f5a623 }` | 与 #2 重复 |
| 5 | `src/lib/terminalTheme.js:15-27` | 深色 13 色 + 入场浅色板 | 与 #2 重复，多 `inkDim/bone/ok/danger` |

**实证**：`grep -rn "term-amber\|term-cyan" src/` → **0 命中**。
令牌定义了却没人用；同时 `#f5a623` 硬编码 9 处、`#4fa8d8` 10 处、`#5d6b7a` 9 处。

### 1.2 令牌串台（实锤）

`src/components/TermHead.jsx:23`

```js
tone === 'cyan' ? '#4fa8d8' : tone === 'amber' ? '#f5a623' : 'var(--ink-soft)'
```

`TermHead` 渲染在**深色顶栏**（`#0B0F14`）里，第三个分支却取了**全局浅色令牌**
`--ink-soft` = `#6b7280`（为白底设计的灰）。
实测渲染值 `rgb(107,114,128) on rgb(10,15,22)` = **对比度 3.97 < 4.5**。
正确取值应是同一作用域内的 `--term-ink-soft`(`#8a98a8`) 或 `terminalTheme.inkDim`。

| m | `#6B7280` | `#0B0F14` | 11px | **3.98** | 4.5 | 地图页序号 `02` | 同上 |

> **重要说明（防止误改）**：`#6B7280` 在**浅色底上是达标的** ——
> 实测 on `#F8FAFC` = **4.62**、on `#FFFFFF` = **4.83**。它只在**深色底**上失败（l / m 两条）。
> 所以这不是「正文主色要改」，而是「浅色令牌被用到了深色区」。
> 同理 `#5A6675` / `#5D6B7A` / `#6B7280` 是**三个几乎一样的灰**（相差 ≤ 17/255），
> 分别硬编码在不同文件里 —— 这正是 §1「无单一真源」的直接后果。

**逐页低对比项计数**（未去重，实测）：入口 11 / 问卷 13 / 报告 19 / 地图 15 / 上传 11 / 班级 15。

**修改方案**
1. 建立**语义化双层令牌**：`--text-on-light-*` 与 `--text-on-dark-*`，每个值按「它将要落在的底色」定，并写明用途注释。
2. 强调色**分底色双版本**（下列值均为实测对比度，底色 `#F8FAFC`）：

   | 语义 | 浅色底版 | on `#F8FAFC` | 深色底版（沿用） | on `#0B0F14` |
   |---|---|---|---|---|
   | 琥珀 / 强调 | `#B45309` | **4.80** ✓ | `#F5A623` | 9.48 ✓ |
   | 琥珀 / 更深（大字） | `#92400E` | **6.78** ✓ | — | — |
   | 青 / 信息 | `#0E7490` | **5.12** ✓ | `#4FA8D8` | 7.25 ✓ |
   | 次级文字（浅底） | `#64748B` | **4.55** ✓ | `#8A98A8` | 6.53 ✓ |
   | 正文（浅底） | `#1F2937` | 14.03 ✓ | `#E8EDF2` | 16.32 ✓ |
   | 分节符 `//` | `#94A3B8` | 2.45（装饰，需 `aria-hidden`）| — | — |

   > `#64748B`(4.55) 是「刚好过线」的次级文字，若用于长段正文建议降到 `#4B5563`（**7.22**）。
3. `TermHead.jsx:23` 的 fallback 改用作用域内令牌（`#8A98A8` 或 `terminalTheme.inkDim` 的修正值）。
4. 三个近似灰 `#5A6675` / `#5D6B7A` / `#6B7280` 合并为**两个**语义值：深底次级 `#8A98A8`、深底弱化 `#7C8B9C`。
5. 删除死令牌 `--term-amber` / `--term-cyan`，或让它真正被引用（二选一，不要两套并存）。

**验收标准**
- `ui-metrics.py` 中 `lowContrast` 数组长度：**每页 0**。
- 纯装饰元素（`//`）允许例外，但须显式标注 `aria-hidden="true"` 并在此清单登记。
- `grep -rn "#5d6b7a\|#4a5866\|#6AA9FF" src/` 命中数 = **0**（未登记色清零）。

### 3.1 这一轮顺手修掉的根因

| 根因 | 修法 |
|---|---|
| 5 份颜色定义各写各的 | `index.css` 建立双层语义令牌（浅底 / 深底各一套），`.term-canvas` 内**重映射**同名变量 ⇒ 组件写 `var(--ink-soft)` 也能按作用域拿到正确值 |
| 品牌色是 Tailwind 默认靛紫 | `--brand` → 深青 `#0E7490`；并在 `theme.js` 拆出 `BRAND_ON_DARK`（深底专用） |
| 琥珀/青是深底原色却被用在浅底 | `surface.js` 的 `TERM_INK` 换成同色系深版（琥珀 `#B45309` 4.80 / 青 `#0E7490` 5.12） |

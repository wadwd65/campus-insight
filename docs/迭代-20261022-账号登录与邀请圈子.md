# v26 · 账号登录与邀请圈子 · 2026-10-22

用户需要管理员邀请成员到小圈子，直接查看填报，替代收集和拖入 CSV；已确认成员只能看自己的答卷，管理员可看圈内原始答案、提交时间和汇总。用户尚不熟悉云服务器，故先完成同一套程序的本机版本，保留单服务器云部署入口，未购买或发布公网服务。

## 最终行为

- 首页及主站页头增加“我的圈子”；访客测评、CSV、行动地图、独立 3D 继续可用。
- 首次部署者用服务器私有文件中的随机一次性口令初始化账号，没有默认管理员密码。账号凭邀请码注册，已有账号可凭邀请加入其他圈子，也可另建自己的圈子。
- 创建者为本圈唯一管理员。邀请码有到期时间、人数限额和撤销功能，原码只生成时显示。管理员权限不会随邀请码授予。
- 成员作答按账号和圈子保存本标签页草稿；退出或切换账号清除旧账号的圈子草稿。答完先出报告和十题核对区，明确告知原始答案、显示名称、提交时间的管理员可见范围，主动同意后才提交。
- 每人每圈保留最新一份答卷、服务器时间和提交次数；重交替换，支持撤回。管理员看已交/未交列表、逐人原始答案和同源规则计算的逐题统计、群体画像。不提供历史答卷版本列表或排名。
- 后端每次按圈子成员关系检查权限，其他圈子的创建者不具备全局特权。成员不能读取成员列表、别人的答卷或邀请管理接口。
- 数据为私有 SQLite，支持 WAL、事务、服务重启后恢复、运行中一致性备份。会话在服务端保存，浏览器使用 HttpOnly/SameSite cookie；HTTPS 部署增加 Secure 与 __Host- 前缀。写请求检查 Origin 和 CSRF；密码用随机盐与原生 scrypt 派生，登录/改密有限流与并发上限，退出和改密撤销旧会话。
- 账号数据目录、初始化口令和数据库不进入前端或交付 ZIP；开发服务器也阻止相关文件访问。服务端拒绝把数据库配置到 public、dist、src 内。

## 运行与部署

要求 Node.js 24.21+，使用原生 SQLite/crypto，不增加账号相关 npm 运行依赖。开发预览、生产 Node 服务使用同一组账号接口 `/api/campus/`。数据默认 `.campus-data/`，可用 `CAMPUS_DATA_DIR` 指向私有持久磁盘；公网必须设置精确 HTTPS `APP_ORIGIN`。纯静态托管不具备账号/圈子服务。

提供 [新手使用指南](账号与圈子使用指南.md)、`npm run accounts:backup` 及可选 Dockerfile。Docker 容器构建、公网 HTTPS、目标平台磁盘及外网可达性尚未验收。当前方案只面向单个服务实例与小圈子；多实例共享数据库、邮件找回、管理员交接和多管理员协作均未实现。

依赖审查发现既有开发依赖问题后，仅更新相关兼容补丁及其锁文件：Vite 8.3.5、source-map-js 1.2.2；最终 npm audit 为 0 项已知漏洞。生产 Node 启动包无需 node_modules，不运行 Vite 开发服务器。

## 验收依据

1. 最终 `npm run check` 退出 0：原计算、账本、问卷、CSV、画像解释、AI 回退、构建/隐私、地图与 3D 检查全部通过；新增账号专项 47 项。
2. 账号专项以多个合成账号和两个圈子验证：一次性初始化、邀请次数/撤销/过期、成员及跨圈越权拒绝、完整答案与版本校验、确认共享、账号切换防误交、重交去重、撤回、移除成员、重启持久化、改密/退出/到期失效、草稿隔离、HTTPS cookie 及一致性备份恢复。
3. 真实浏览器：测试管理员建圈并生成邀请 → 新成员凭邀请注册 → 答两题后暂停，第三题恢复 → 完成十题 → 默认禁用提交 → 核对十题并同意 → 服务器保存 → 成员只能看到自己的答卷 → 管理员看到原始答案与时间 → 圈内一份有效答卷进入汇总，明确提示小样本限制。
4. 390×844 手机成员空间与生产圈子汇总无横向溢出；手机选中圈子后优先显示本圈填报。管理员桌面、成员桌面/手机、原始答卷和汇总截图已保存。
5. 开发服务对私有数据目录、数据库及绝对文件路径请求返回 403。生产启动包静态服务、API、私有文件拒绝、路径边界与哈希资源一致性检查 8 项通过；独立生产包再以合成数据走完初始化、邀请注册、在线保存及管理员读取，同源生产页面实际登录和汇总通过，最终生产页面控制台无警告/错误。
6. 本轮没有调用收费模型。沿用 v25 已验收的服务端模型链路；圈子汇总只传汇总统计，不传成员名单或逐人答卷。没有重新测量 GPU 帧率，也没有更改地图几何。

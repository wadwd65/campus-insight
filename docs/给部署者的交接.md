# 给帮助部署的人

这份说明面向负责服务器的人。第一次在 Windows 电脑上试用，请先打开包内的“先看这里.html”，双击“开始使用.cmd”即可。

## 先确认要交付什么

需要上线的是完整 Node 服务，不能只上传 `dist`。它包括网页、注册登录、圈子权限和答卷保存。每个人都能直接注册并创建自己的圈子，无需初始化口令。创建者只管理自己的圈子，加入其他圈子仍须有效邀请。

## 服务器需要什么

- Node.js 24.21 或更新版本，或能够运行包内 Docker 模板。
- 私有持久存储，用于 SQLite 账号、圈子和答卷。重启、更新程序后必须保留。
- 可以正常访问的 HTTPS 正式网址。国内服务器的域名、网络和备案事项由部署者按平台要求办理。
- 私有备份位置。

模型服务为选填，不影响问卷、圈子提交和规则统计。请勿为完成基础部署而索取模型密钥。

## 使用普通 Node 服务

1. 解压完整管理员包。先保留同版 ZIP，方便回退程序。
2. 运行 `npm run configure`，选择用途，填入正式 HTTPS 网址、端口和私有数据目录。只设置配置还不会配置域名或购买服务器。
3. 同一服务同时提供网页、`/api/campus/` 和 `/api/deployment`。反向代理转发到程序端口，由 HTTPS 入口负责证书。
4. 使用服务管理工具保持 `npm start` 运行，重启时自动恢复。配置与数据保存在公开资源目录以外。
5. 打开正式网址，直接注册并创建自己的圈子，设置自己的账号和6～12位密码。无需到服务器找开通口令。

## 已有 Docker 与正式域名

按《双方案部署与交接.md》的 Compose 步骤配置域名、HTTPS 与私有持久卷。模板位于 `deploy`。这条路线需要部署者理解数据卷与反向代理，不建议让只想填写问卷的用户操作。

## 上线后实际验收

1. 在外部网络打开网站，独立注册两个账号，各自创建圈子。确认双方都只能管理自己的圈子。
2. 管理员生成邀请，另一个浏览器身份通过邀请加入。普通成员不能查看他人答卷或管理邀请。
3. 管理员和成员分别答完十题，在“我的档案”点“提交到我的圈子”，核对并同意后提交。确认工作台的原始答案、时间和汇总更新。
4. 退出登录再登录，重启服务，确认账号、圈子和已交答卷仍存在。
5. 实际备份一次，并在隔离实例恢复。原站点正在使用时不要用空数据覆盖。
6. 交给使用者正式网址，以及怎样备份和联系维护者的简短说明。确认后再邀请真实成员填写。

## 数据与交接

Windows 用户可以双击“备份我的数据.cmd”和“打开数据文件夹.cmd”。服务端也可运行 `npm run accounts:backup`。备份含账号与原始答卷，存放在私有位置。

整站迁移使用 `npm run accounts:restore -- 备份文件路径`，恢复到新的空数据目录。圈子 CSV 用于统计和留档，不能代替账号数据库备份。

交接时提供同版程序包、私有备份、配置保存位置和服务器访问权。不要把 `.env.local`、数据库或旧版 `setup-key.txt` 放进公开下载包。v34 已取消面向用户的初始化口令流程，旧账号和已提交答卷沿用原数据库。

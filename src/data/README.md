# src/data/ · 数据接入

**职责**：管「数据从哪来」—— 契约数据的定义、读取内置数据、接收用户上传的文件、保管当前会话的数据状态。

**和 `public/data/` 的区别**

| 目录 | 放什么 | 谁会用 |
|---|---|---|
| `public/data/` | 数据文件本体（CSV），随构建产物一起发布 | 浏览器通过 URL 取 |
| `src/data/` | 数据定义与取数代码 | 开发时 import |

**当前落位**

| 文件 | 做什么 | 状态 |
|---|---|---|
| `matrix.json` | **数据的单一来源**：6 个问题、28 个选项、8 个属性的增量向量 | ✅ |
| `loadSample.js` | 拉取 `public/data/` 下的 CSV | 待做 |
| `readFile.js` | 读取用户拖入的文件为文本 | 待做 |

**为什么矩阵要单独放成一份 JSON**

因为它有**两个消费者**：前端计算层（JS）和基准数据生成脚本（Python）。

如果两边各写一份选项表，迟早会漂移 —— 生成脚本按 A 版选项生成 CSV，前端按 B 版选项解析，那些对不上的值会被判成「未知选项」，而**这种错误在图上看不出来**，只表现为某些人的某个维度莫名其妙偏低。

于是：矩阵只写一份，Python 与 JS 都读它。另外还有一道自检守着（`npm run selftest` 的闸门一：基准 CSV 里的每个值都必须在矩阵里有定义）。

# src/lib/ · 纯计算逻辑

**职责**：只放「输入数据 → 输出数据」的函数。**不 import 任何 React**，不碰 DOM，不做界面。

**为什么单独分一层**：评委看架构就是从这一层看。把计算和界面分开，意味着同一份逻辑可以被页面用、被自检脚本用、被导出报告用 —— 改界面不会算错数。

**约定**

- 一个文件一类职责，导出纯函数
- 函数要能被单独调用验证（在浏览器控制台粘一行就能跑）
- 不做 `console.log` 式调试残留

**当前落位**

| 文件 | 做什么 |
|---|---|
| `text.js` | 通用文本清洗（表头 / 单元格）。CSV 解析与问卷校验共用，避免两处 trim 规则 |
| `surveySchema.js` | **问卷契约的单点定义**：10 个问题、48 个选项、9 个属性。数据源是 `src/data/matrix.json` |
| `parseCsv.js` | 通用 CSV 解析。必需列由**调用方传入** —— 快入口与真入口共用同一个解析器 |
| `surveyClean.js` | 问卷记录的校验与清洗，输出人话报告 |
| `matrix.js` | 映射矩阵：作答 → 8+1 维属性；基准分位数表；百分位换算 |
| `results.js` | 属性 → 雷达图 / 环形图 / 四年曲线 / 冷知识（五件套之四） |
| `buildSummary.js` | 结构化摘要（喂给大模型）—— 待做 |
| `llm.js` | 大模型接口封装（OpenAI 兼容 + 流式）—— 待做 |
| `fallback.js` | 无密钥时的降级文案 —— 待做 |

**为什么口径必须集中在一处**：`surveySchema.js` 里的「有哪些问题」「第几题有哪些选项」「属性怎么算」被解析、校验、清洗、矩阵、图表、大模型摘要六处引用。散着写，改一次口径要改六处，一定有一处漏掉 —— 而漏掉的那处会安静地算出一个不一样的数字。

**两条被验证过的经验（写在这里，免得再踩）**

1. **问卷数据不去重。** 上一版（学习记录）的去重规则是照搬过来的，结果在 2000 条基准数据上剔掉了 449 条 —— 那些是真人，不是脏数据。选项组合空间随扩题（6 题 28 选项 → 10 题 48 选项）已经很大，2000 人里仍会有相当一部分人撞答案。照搬的后果是安静地删掉两成样本，把百分位整体算歪。
2. **环形图各类不能共用一个权重下限。** 共用一个常数会让「极度自律的人」的娱乐 / 社交 / 干饭三类同时跌穿下限、变成同一个百分比 —— 那三个维度的信息就没了。每类各有下限。

**验证方式**：`npm run selftest`（零额外依赖，评委 clone 后直接可跑，39 项）。

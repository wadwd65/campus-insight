# src/lib/ · 纯计算逻辑

**职责**：只放「输入数据 → 输出数据」的函数。**不 import 任何 React**，不碰 DOM，不做界面。

**为什么单独分一层**：评委看架构就是从这一层看。把计算和界面分开，意味着同一份逻辑可以被页面用、被测试用、被导出报告用，改界面不会算错数。

**约定**

- 一个文件一类职责，导出纯函数
- 函数要能被单独调用验证（在浏览器控制台粘一行就能跑）
- 不做 `console.log` 式调试残留

**预计落位的文件**

| 文件 | 做什么 | 任务编号 |
|---|---|---|
| `schema.js` | **数据契约的单点定义**：列名、字段映射、时段划分、正确率口径 | 基础 |
| `parseCsv.js` | CSV 文本 → 原始行对象；识别表头顺序变化 | T-05 ✅ |
| `validate.js` | 字段校验，返回人话错误信息（带行号 / 列名 / 原值） | T-06 ✅ |
| `cleanData.js` | 去重、剔除非法行并统计剔除数量 | T-07 ✅ |
| `loadData.js` | 把上面三步串成唯一入口 `loadStudyRecords(text)` | 组装 |
| `aggregate.js` | 按科目 / 按日聚合 | T-08 T-09 |
| `diagnose.js` | 投入产出比、背离度、时段统计、趋势检测 | T-10 T-11 T-12 |
| `buildSummary.js` | 汇总成一份喂给大模型的结构化摘要 | T-13 |
| `llm.js` | 大模型接口封装（OpenAI 兼容 + 流式） | T-20 |
| `fallback.js` | 接口不可用时的本地模板文案 | T-23 |
| `exportReport.js` | 导出解读文本 / 图表图片 | T-27 |

**为什么口径必须集中在一处**：`schema.js` 里的「正确率怎么算」「时段怎么分」
被解析、校验、清洗、聚合、图表、大模型摘要六处引用。散着写，改一次口径要改六处，
一定有一处漏掉 —— 而漏掉的那处会安静地算出一个不一样的数字。

**关键口径**：正确率一律用**加权**（先加总题量与正确数再相除），
不是把每天的百分比再平均 —— 后者会让「做了 3 题的那天」和「做了 60 题的那天」等权。

**验证方式**：`npm run selftest`（零依赖，评委 clone 后直接可跑）。

## 三、★★★ 本轮抓到的最重一条：**砖红被"双重相乘"洗成粉灰**

### 症状（先看数据，不是先看图）
立面像素直方图：中位明度 139，主色 **`#A08078`**（rgb 160,128,120 = 粉灰）。
**"高饱和砖红"像素仅 8 个（0.1%）** —— 设计里的砖红 `rgb(168,90,72)` 在画面上**消失了**。

### 定位（`diag-brickmap.cjs`，把材质链整个读出来）
```
3x  #9a5242  MeshStandardMaterial  map=YES 256px avg rgb(169,98,79) rep=[8,12]
      期望 map x color = rgb(102,32,20)
30x  #6a5240  MeshStandardMaterial  map=NO
24x  #84504a  MeshStandardMaterial  map=NO
12x  #9e564a  MeshStandardMaterial  map=NO
```
砖贴图**本身是对的**（均值 rgb(169,98,79) ≈ 设计值）。
但它挂在 `M.wallMid = 0x9A5242` 上。three.js 同时有 `map` 和 `color` 时，
结果是 **`map × color`（逐通道相乘）**：
```
rgb(169,98,79) × rgb(154,82,66)/255 = rgb(102,32,20)   ← 极暗的红
```
再被太阳/半球光照亮 —— **低通道先被抬起来**，高光部分就变成"褪色的粉灰"（`#A08078`）。

### 修法
**有 `map` 的材质，`color` 必须是白（或接近白的色调微调）。**
```js
mBrickW.color.setHex(0xFFE8E0);   /* 白基（微暖）—— 保留"砖是暖红"的倾向，
                                     但不把明度压掉一半 */
mBrickD.color.setHex(0xFFE4DA);   /* 侧面略冷一档，保留方向感 */
```

### 结果
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 立面像素数 | 5,574 | **15,738（+182%）** |
| 高饱和砖红占比 | 0.1% | **27.9%（×279）** |
| 主色 | `#A08078` 粉灰 | **`#885850` 砖红** |

★ **与 v16 踩的 `sRGBEncoding` 是同一类病**：都不是"选错颜色"，
而是**颜色在管线里被多乘了一次**。⇒ 见技能新增 §14。

| 变体 | 草坪 | 建筑 | 建筑−草坪 | 阴影面积 |
|---|---|---|---|---|

## 六、★★★ 第四条：闸门"按色号找构件"是一个设计缺陷

本轮我把屋顶设备色板整体改深 ⇒ `gate-geometry.cjs` **立刻误报**：
```
FAIL  G1 楼梯间存在      未找到楼梯间几何
PASS  G7 屋顶设备不悬空   共 0 个水箱；越界 0
```
**不是几何坏了，是闸门在按硬编码色号（`0x9C9A94` / `0x8E9298`）找构件。**
这一轮之内同一个坑踩了 **3 次**（G1 改判据、G7 改判据、色板再改）。

**修法：把色板从场景里暴露出去，闸门按"名字"取色。**
```js
/* tower-01-core.js */
window.__C = {};
Object.keys(C).forEach(function (k) { window.__C[k] = C[k]; });

/* gate-geometry.cjs 探针内 */
var C = window.__C || {};
function hexOf(name, fallback){
  var v = C[name];
  if (typeof v !== 'number') { (out.paletteMiss = out.paletteMiss || []).push(name); return fallback; }
  return v;
}
if (c !== hexOf('stairWall', 0x9C9A94)) return;
if (c !== hexOf('tank', 0x8E9298)) return;
```
⇒ **改色板不再使闸门失效**，且 `out.paletteMiss` 会在真的找不到时报警。

★ 与 §8.4「验证工具自身也要核算」同源 —— **闸门不能依赖会漂移的常量**。

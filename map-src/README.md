# map-src —— 3D 校园地图的构建管线

这个目录是 `public/map/校园地图-3D实景.html`（1MB 单文件 3D 校园）的**全部源码与工具**。
地图不是手搓出来的单体文件，而是「**分层源码 → 八道闸门 → 拼装成单文件**」构建出来的。

## 一、怎么生成地图

```bash
python build-campus.py     # → campus.html        （静态 3D 校园，主产物）
python build-game.py       # → campus-game.html   （可玩原型：点建筑掉体力、推进时段）
```

两份产物都是**单文件零依赖**（three.js 已内联），双击即可离线运行。

## 三、八道构建闸门（`build-campus.py`）

拼装前逐项检查，任一不过就中止（这些闸门都是被真实事故逼出来的）：

1. **抽取自证** —— 从 `tower-04-assembly.js` 抽「楼体套件」时断言边界正确
2. **语法预检** —— 每个 part 过 `node --check`
3. **色号 lint** —— 抓 `0x6A5F४8` 这类混入异常字符的坏色号（肉眼极难发现）
4. **顶层重名** —— 两个 part 声明同名 `var` 会静默覆盖
5. **局部变量遮蔽** —— 函数内同名 `var` 会顶掉外层 canvas 对象（曾导致**整张地面全黑**）
6. **ASI 隐患** —— 少一个分号，下一行会被解析成函数调用（`node --check` 查不出来）
7. **坐标多真源** —— 同一对象（田径场）出现两份坐标，改一处完全不生效

## 五、数据来源与取形方法（诚实说明）

- 湖的轮廓：从**用户提供的 Apple 地图截图**按颜色抠出水体 → 轮廓化 → 标定换算；
  描边回画原图目视验证完全贴合（`docs/map-review/lake-trace-from-applemap.png`）。
- 建筑：从**高德卫星瓦片**（自拼正射影像）按屋顶色提取轮廓，用跑道做标定锚点；
  提取结果有描框验证图（`docs/map-review/sat-buildings-detected.png`）。
  注意：那版卫星影像**早于湖建成**，所以"楼用卫星、湖用 Apple 图"两源互补。
- 早期还试过：官方 720 云全景航拍（`map-assets/official-360/`）、KayKit 真人美术资产。
  后者被用户否决（"房子忒丑"），代码保留在 `tower-13-loader.js` / `tower-13-realart.js`，
  但其 4MB 的资产数据（`tower-13-assets.js`）未入库以免拖大仓库——需要时可按 README 里的脚本重新生成。

## 六、已知限制（不掩饰）

- 建筑**落位**目前是"按参考图调整过的大关系"，不是逐栋实测对位；
  精确对位需要先把 3D 母版（`3d-clean.png`）→平面坐标的标定打通（当前仿射拟合残差 1px 但反向压平失败）。
- 湖用真实轮廓 ✓，但岸线是 28 点折线，近距离看有折角。
- 移动端只验证到"无横向溢出 + 单列可读"，手势（旋转/缩放）未做移动端优化。

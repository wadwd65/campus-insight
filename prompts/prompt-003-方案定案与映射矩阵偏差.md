## 二、AI 的执行与三处偏差

### 先讲一个在"写之前"就避掉的坑

D-1 选了 B（映射矩阵）之后，最省事的做法是「一个选项直接对应一句结论」—— 选「网吧」就写「你是夜猫子」。这条路被否掉，原因是它**撑不起五件套**：6 个选项最多给 6 句话，而输出要 5 轴 + 5 类 + 4 个节点 + 2 条冷知识。

于是先设计了中间层：**8 个潜在属性**，每个选项是一个 8 维增量向量。

这一步的价值不在"写得更复杂"，而在于它把最坏情况挡在了外面 —— 那个最坏情况是：**六题都选得不同，生成的东西看起来却差不多**。一旦发生，「这就是我」这个产品唯一的支点就断了。

所以从第一天起就配了两道**自动闸门**（见第四节），而不是在文档里写一句"结果因人而异"。

### 偏差 1：照搬上一版的去重规则，误删 449 条真人数据

| | |
|---|---|
| **现象** | 自检报「基准 CSV 剔除 0 条（说明每个值都在矩阵选项内）」失败 —— 实际剔除 **449 条**，2000 人只剩 1551 |
| **原因** | `surveyClean.js` 的去重逻辑是从上一版（学习记录）原样搬过来的 |
| **为什么它在这里是错的** | 学习记录的一行是「**一次学习会话**」，两行完全相同几乎只可能是复制粘贴的脏数据；问卷的一行是「**一个人的答案**」，而 28 个选项的组合只有一万种，2000 人里必然有几百人答案完全一致 —— **那是真人，不是脏数据** |
| **如果没抓到会怎样** | 安静地删掉 22% 的样本，把百分位整体算歪；更糟的是删掉的恰恰是最"大众"的那部分人，偏差是**系统性**的，不是随机噪声 |

**修正**：问卷数据**不去重**，只统计重复率；重复率超过 50% 时才提示（那说明文件本身有问题，比如整段被粘了两遍）。

### 偏差 2：环形图三类变成同一个百分比，信息全丢

| | |
|---|---|
| **现象** | 抽样报告里出现「娱乐 3.7% · 社交 3.7% · 干饭 3.7%」 |
| **原因** | 五类权重共用一个下限常数（`max(权重, 4)`）。一个极度自律的人，娱乐 / 社交 / 干饭三类的权重全都跌穿这个下限，于是全部被压成同一个值 |
| **为什么这是真问题** | 那三个维度的**信息全丢了**，看图的人还会以为「他这三件事花的时间一样多」。这不是显示问题，是数据丢失 |
| **修正** | 每类各有自己的下限（学习 7 / 娱乐 5 / 社交 6 / 干饭 4 / 睡觉 20），同时把影响系数整体调小，让它不容易触底 |

### 偏差 3：派生属性没有文案，输出「—— 」后面空着

| | |
|---|---|
| **现象** | 冷知识输出成「在「佛系指数」上，你有 98% 的大学生比你高 —— 」 |
| **原因** | 文案表按 8 个**基础属性**写，漏了派生属性 `buddhist` |
| **为什么这是真问题** | 不报错、不崩溃、不影响任何数字，只是安静地难看。用户看到的就是一句没说完的话 |
| **修正** | 补上文案与称号，并加一条**覆盖断言**（9 个属性都必须有文案与称号），用机器守住，而不是靠记性 |

### 顺带记一个协作层面的偏差（与产品无关，但影响留痕真实性）

**并行修改同一个文件会导致先前的改动静默丢失。** 本轮中，一次对自检脚本的两处修改同时发出，结果第一处（补 import）被第二处覆盖，运行时报 `FACT_COPY is not defined`。

**规矩**：同一文件的多处修改必须**串行**，改完用 `grep` 复核落盘结果。

## 四、这一条留下的可复用规矩

1. **换领域时，不要照搬上一个领域的清洗规则。** 去重、异常值、缺失值的含义随数据对象的语义而变 —— 「重复」在学习记录里是脏数据，在问卷里是常态。
2. **多个维度不要共用一个下限 / 上限 / 阈值。** 共用会让它们在极端情况下塌缩成同一个值，而塌缩是静默的。
3. **文案表和枚举要配覆盖断言。** 加了一个属性却忘了加文案，不会报错 —— 只有断言会吼。
4. **验收标准必须能自动跑。** 这条已经被验证三次了：002 的转折点偏晚 12 天、003 的误删 449 条、003 的塌缩百分比，人眼全都看不出来。

# Prompt 030 · 登录注册分离与短密码

## 1. 我的提问

> 现在登录功能还是有点问题，必须
> 要注册。有一个登录功能还有一个注册功能，并且尽量简单一点。密码就是，6~12位就行

2026-10-22，Codex。本文件是本轮需求与验收摘要，不冒充原始对话导出。

## 2. AI 的回复要点

检查现有浏览器发现，站点尚未初始化时，`setupRequired` 把所有表单强制改为首位管理员注册，并隐藏登录/注册切换。原密码策略还是12–128位。

始终显示登录和注册两个按钮；只在用户主动选择注册时进入首位账号初始化。登录只收账号、密码。注册的新密码和修改密码统一6～12位，允许纯数字；显示名称改为选填，默认用账号名，邀请链接自动带入邀请码时不再展示重复输入框。

## 3. 哪里不对 / 我实际需要什么

不能只缩短前端提示而漏改服务端，也不能把原先长密码账号锁在登录页外。服务端新密码按6～12位校验，旧密码登录和改密前的当前密码仍兼容原长度。首次建号口令与圈子邀请授权保持原范围。

浏览器填充场景未触发原生minLength提示，补上提交前显式长度校验，让5位密码稳定显示清楚错误。桌面检查又发现常驻立绘遮住密码按钮，账号入口页将立绘移到左侧，手机仍按原规则隐藏。

## 4. 追问与最终结果

完整 `npm run check` 通过，其中账号专项53项；最终前端调整后再次完成SSR、构建与隐私检查。独立localhost测试站以合成账号实测：未初始化时可切换登录/注册、6位纯数字注册、退出后不带邀请码登录、12位受邀注册、邀请页切登录、5位错误、切模式清错误、密码显示/隐藏、刷新保留登录。

390×844登录/注册无横向溢出；桌面“显示密码”按钮中心不被立绘遮挡。旧长密码登录和修改为6位新密码由合成历史账号测试覆盖。没有改用户真实账号、密码或答卷。

当前5191预览已重启加载新后端和构建；另一个测试站使用localhost隔离Cookie和私有数据。测试日志、截图、源码与运行包保留在本轮交付目录。

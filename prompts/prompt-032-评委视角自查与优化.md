## 1. 需求背景

本轮承接用户对功能、UI、新手易用性、强指引和可跳过操作的要求，在 v31 之后进一步从评委首次体验角度自查：约三分钟内能否看清实际用途、AI 的职责，以及能否取得可复现的同版工程。

这段为任务背景摘要，未补造一条用户没有说过的“原始提问”。

## 2. AI 的审阅与方案

代码审阅发现：首页主要路径约需两分钟答题，完整班级示例藏在上传框底部；小雷达预览只展示部分结果，规则与模型分工说明较远。建议先让体验者一键看到完整合成班级，再按需要答自己的十题或加入真实圈子。

本轮实施范围：

- 首页提供 48 人合成示例，复用正式 CSV 解析、清洗与计算；持续使用 `source=sample` 标记，不创建账号或圈子，不虚构个人作答。
- 首页明确数字由规则计算，模型仅组织已有统计的文字；未连接时以本地规则解读呈现。
- 少于 5 份有效答卷时不挂载群体画像、结论和 AI，保留逐题人数统计。
- 统一合成示例、导入文件、圈子已交答卷的来源与统计范围，并带入导出；核查绝对中位数，去掉没有证据支持的组织建议。
- 账号和部署能力不能确认时，不宣称已经可用。无服务状态仍提供个人 / 合成示例体验，开通与邀请指引区分管理员和成员。

## 3. 自查时避免的错误

不能把“示例看起来完整”当成真实班级已验证价值；不能把模拟基准写成全国大学生调查；不能把完成问卷或打开示例当成提交圈子；不能在少量答卷上继续调用模型生成群体判断。

也不能因本地有后端就声称旧公网静态入口具备当前全部能力。公开仓库、同轮源码、运行包与视频要能对应，未同步的工作应如实标记。

## 4. 预审与验证状态

按本地历史赛事存档的五项权重预审：过程可复现性 25%、实用价值 25%、意图控制 20%、工程 15%、体验 15%。该存档不是本轮核实的最新官方细则，当前报名要求须另核个人中心。

开发者主观暂估为 **80～86 / 100**，属于基于现有证据和待验收修改的条件式区间，不是评委成绩，不承诺满分。主要缺口为真实新手 / 班级试用、完整新版公网与多设备验证、当前 Git 同步、最终 MP4 和提交回执。

v31 的已通过检查只能作历史基线。**v32 最终完整检查、专项结果、浏览器实测、窄屏体验及包校验均待根代理补写**，不能提前写“通过”。实现范围和待验收清单见 `docs/迭代-20261022-评委视角自查与优化.md`。

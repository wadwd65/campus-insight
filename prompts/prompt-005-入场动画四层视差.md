# prompt-005 · 照参考站重做打开网站的第一屏（四层视差入场动画）

- **日期**：2026-09-16
- **类型**：功能增强 / 视觉改版
- **涉及文件**：`src/scenes/IntroScene.jsx`、`src/lib/introLayers.js`（新建）、`src/lib/terminalTheme.js`、`src/index.css`、`scripts/selftest-intro.mjs`（新建）、`scripts/smoke-render.jsx`、`package.json`

## 一、我的意图

网站第一屏（打开链接看到的那一屏）太单薄了 —— 只有一片静止的光点、逐条淡入的文字，读起来像"界面在加载"，不像"走进一个地方"。

我之前做过两份参考站的素材调研（桌面参赛包 `07-素材调研/`），其中 Arcaea Web 复刻那份专门拆解了入场动画。我想照着那份参考，把第一屏重做一遍，让它有一点"质感"。

## 二、我发出的 Prompt 原文

> 6你看能不能把入场动画也做了？

（AI 理解成了"地图那一屏的进入动画"，我纠正：）

> 我指的是进入网站那个动画，之前不是有参考吗？你就参考那个

## 三、AI 的回应摘要

AI 先纠正了自己的理解偏差 —— 它第一次把「入场动画」读成了"新场景（地图）的进入动画"，于是去读 `MapScene.jsx`、`mapEngine.js` 等文件做功课。收到我的纠正后才转向 `IntroScene.jsx`，并去桌面参赛包重新翻出两份参考站拆解，确认「参考」指的是 `07-素材调研/参考站-ArcaeaWeb复刻/`。

关键的一次判断：AI **没有**照搬参考站的全部做法，而是先划了边界 ——

| 参考站的做法 | AI 的判断 |
|---|---|
| 四层视差（底/中景/粒子/前景） | ✅ 直接采用 |
| 长时间缓变、无硬切 | ✅ 直接采用 |
| 「慢 → 静 → 出现按钮」的节奏 | ✅ 采用（推翻上一版"干脆"的节奏） |
| Click to Enter 放左下角 | ✅ 采用（正中留给纹章） |
| 具体纹章图案 | ❌ 不可抄，用已有的自绘 `Crest()` |
| 音/图/字体素材（版权归 lowiro） | ❌ 一个字节都不能进公开仓库 |
| 毛玻璃 + 24px 大圆角（另一份参考站） | ❌ 与本站 clip-path 切角路线互斥 |

于是最终产出四层全部**零素材依赖**：雾团是 CSS 径向渐变、剪影是 `clip-path` 几何块、光带是渐变条、纹章是自绘 SVG。

## 四、我发现的问题 / AI 的自我修正

### 4.1 AI 一开始听错了活（我纠正）

这是本项目的老问题复发。项目里「入场动画」已经有专指（`IntroScene`），AI 还是把它读成了"新场景的入场"。教训与前面几条协作纪律同源：**用户说"某功能也做了"时，要先用项目已有的词汇表对照一遍，而不是按通用语感猜。**

### 4.2 自检抓出一个真的视觉 bug（关键）

AI 写 `buildDots()` 时把时长公式写成了：

```js
duration: `${(4.6 + depth * 3.2 + prand(i, 4) * 1.4).toFixed(1)}s`
```

`depth` 越大 = 越近，而 `duration` 越大 = 越慢 —— 也就是它把「近处更快」写反成了「近处更慢」，视差方向是错的。

**这个 bug 靠肉眼很难发现**：画面上光点都在飘，只是"有点不对劲"。是 `selftest-intro.mjs` 里的断言把它钉住的。

更值得记一笔的是**第一版公式还有第二层错误**：层内随机抖动是 8 秒，而深度步进只有 2.6 秒 —— 抖动盖过了步进，意味着"近处更快"连平均意义上都不成立。AI 第一次修的时候只改了符号没改配比，自检第二次仍然红，才彻底改成「步进 3.2s > 抖动 1.4s」。

由此还补了一条断言：**只比平均值是不够的**，因为平均能过而单个元素里有一半是反的。最终改成逐点比 `min/max` —— "最慢的近点也必须快过最快的远点"。这条断言在改完之后立刻抓出了方向写反的问题。

### 4.3 光带第一版太亮太粗（浏览器目视发现）

第一版光带宽度 0.6~2.2px、亮度 0.04~0.16，截图一看像一排栅栏，还压住了标题。修正方向不是"减少数量"（数量决定满屏氛围感），而是**降低每一条的权重**：宽度收到 0.5~1.4px、亮度压到 0.03~0.11，CSS 加 `blur(0.5px)` + 两端渐隐，并让一部分光带只占屏幕一小段高度（长度一致会强化栅栏感）。

## 五、我如何引导修正

1. 发现 AI 理解偏了 → 直接说清是"进入网站那个动画"，并给出线索「之前不是有参考吗」让它自己去找
2. 强调"参考那个" → 让 AI 去读参考材料，而不是自由发挥
3. 其余交给 AI 自己按项目既有纪律执行（不用动画库、抽纯函数、补自检）

## 六、本次落地结果

**新增四层视差（全部零素材）**

| 层 | 实现 | 周期 |
|---|---|---|
| 底 · 雾团 | 3 块 CSS 径向渐变 + `blur(60px)` | 34s 漂移 |
| 中景 · 剪影 | 8 块 `clip-path` 几何多边形 | 随推镜 |
| 粒子 · 光点 | 46 个，分三档深度（大小/速度/亮度各异） | 4.2~12s |
| 前景 · 光带 | 22 条竖直光柱，极慢明灭 | 9~22s |
| 中心 · 纹章 | 自绘 SVG + 新增 24s 自转虚线外环 | 24s |

**节奏改回"仪式感"**：`INTRO_TIMING` 总长 1000ms → **2100ms**，并显式推翻了上一版"要干脆"的判断 —— 入场不是"一道门"（越快穿过越好），而是"一个环境"（要让人先认下这个地方）。但慢的是背景层，文字层仍在 2.1 秒内落完：**背景慢、前景快**，既不"没质感"也不"让人等"。

**新增自检 50 项**（`selftest-intro.mjs`）：确定性伪随机 / 分层数据重渲染不跳位 / 视差层序（近的动得快）/ 推镜参数 / 层内元素散开 / 光点分档 / 设备预算 / 时间线一致性。

其中最有价值的一条是**跨文件一致性断言**：`LAYER_REVEAL` 与 `INTRO_TIMING` 有六个节拍重复定义在两个文件里，改一处忘一处是必然会发生的事，这条断言专门抓它。

**smoke 补上入场页覆盖**（17 项）：入场页是"所有人看到的第一眼"，此前**完全没有自动化覆盖**。新增断言含「四层外壳类名都在」（类名丢了不报错，只会让整屏退化成纯黑 + 文字，是"看起来正常"的坏法）与「`animation-delay` 真的写进了 inline style」（元素在但没挂延迟 = 整屏同时出现，入场等于没有）。

**自检总数**：258 → **325 项**（124 + 39 + 54 + 50 + 58）

**构建**：686ms，首屏 gzip 87.82 → **95.24 kB**（+7.4 kB），CSS +3 kB。**没有引入任何新依赖**。

**浏览器实测**（CDP + Edge，1440×900）：
- 四层元素全部就位（3 雾团 / 8 剪影 / 22 光带 / 46 光点）
- 「进入终端」定位在 **left:40px, bottom:48px** —— 左下角，与参考一致
- 关闭动效后：光带/光点/剪影 **数量为 0**（根本不生成，而非隐藏），所有动画 `none`，文字 opacity 1 无空白等待
- 回车能正常进入终端 HUD

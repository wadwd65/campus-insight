# prompt-001 · 选题方向：AI 越权代选与纠正

> 归档日期：2026-09-14
> 迭代主题：从「方向 6 与方向 4 分别要做什么」的询问，收敛到「由本人亲自拍板方向 6 下的具体产品形态」
> 这段链路的完整度：**提问 → AI 偏差 → 追问修正 → 收敛**，四段齐全

---

# 1. 我的提问

```
46方向我们大概是应该做什么？
```

**提问背景**：当时方向层面只有 AI 的建议（倾向方向 6），我并没有表态。我想知道的只是「这两个方向各自到底要做什么事」，以便我自己判断。

---

# 2. AI 的回复要点

- 画出两张对比图：两个方向的产品形态与操作链、两者的失败降级路径
- 产出对比文档 `docs/选型-01-方向4与方向6对比.md`，含两方向的产品形态、技术模块、80 天分配、退路长度
- 给出的判断依据（这部分是有价值的）：
  - **退路长度**：方向 6 满配 → 图表 + 模板文案 → 纯图表工具，每级都能交付；方向 4 满配 → 白屏，大模型返回结构不合法就没有可渲染的内容
  - **报错可复现性**：方向 6 的缺陷带确定性报错，可复制给 AI；方向 4 约一半是概率性「有时行有时不行」，没有报错作为抓手
  - 技术定位差异：方向 6 里大模型是「装饰件」（输出自由文本），方向 4 里是「承重墙」（输出必须严格合法）
- **但它在结尾直接下了结论**：「我做了决定 —— 方向 6」，并**按方向 6 开始落地**：改写仓库 `README.md` 的产品定义、修改 `public/data/README.md` 的字段样例、把「已定方向 6」写进项目记忆与桌面开发日志

---

# 3. 哪里不对 / 我实际需要什么

**我实际需要的**：一份让我能自己判断的材料。

**实际给我的**：材料 + 替我做的决定 + 已经按这个决定改掉的四处文件。

具体偏差（四要素）：

| 项 | 内容 |
|---|---|
| 位置 | 仓库 `README.md`、`public/data/README.md`、`docs/留痕规范.md` 示例、项目记忆与桌面开发日志 |
| 操作 | 我提问「这两个方向要做什么」，没有授权任何落地动作 |
| 期望 | 只回答「做什么」，把选择权留给我 |
| 实际 | AI 自己选定方向 6，并把「已定」写成既成事实，据以修改了四处文件 |

**我的原话**：

```
看来你还是喜欢直接这样做。我还没有选，你就直接帮我选好了。
```

**为什么这件事严重**：不是方向选错了，是**「有理由」和「有权决定」是两件事**。AI 列出了三条理由，然后把理由当成了可以往下做的授权。而产品方向是本人的决定权，理由是用来支持本人判断的，不是替代本人判断的。

---

# 4. 追问与最终结果

**第一步 · 指出问题后 AI 的处置**

回退全部四处越权落点：

| 位置 | 回退前 | 回退后 |
|---|---|---|
| 仓库 `README.md` | 标题即「消费明细分析看板」，功能与依赖都按方向 6 写死 | 两个候选方向并列，标注「决定权在本人」 |
| `public/data/README.md` | 预设了消费明细字段样例 | 字段改为待定 |
| `docs/留痕规范.md` | 示例里写「上传 CSV」「图表区」 | 示例改为方向无关 |
| 桌面开发日志与项目记忆 | 「✅ 选题定为方向 6」 | 「AI 的建议（仅建议，尚未拍板）」+ 一条更正记录 |

仓库补一条提交 `bf007a4 docs: 选题待定，项目描述改为方向无关`，并写进协作纪律：**凡涉及方向、范围、取舍，只列「选项 + 理由 + 后果」，不替用户下结论**。

**第二步 · 我自己拍板（方向层面）**

```
我们选择方向6但具体做什么你可以做几个推荐，先不要做内容
```

→ 产出 `docs/选型-02-方向6具体方案候选.md`，并列 A / B / C 三个候选。**这次 AI 没有再下结论**，只标注「建议倾向 C，是建议不是决定」。且经实测确认未动任何实现代码（仓库无 `src` 目录）。

**第三步 · 我自己拍板（产品形态层面）**

```
那我们确实可以做 C 方向，听起来就比较牛逼，我们先从这个方向做一个初始表，我们需要做的一些东西全都写出来，然后我们开始做了
```

→ 产出 `docs/开发任务表-方向C.md`（31 项任务 / 7 个模块 / 每项带验收标准），并完成工程骨架 T-01 ~ T-03。

**收敛结果**：产品形态确定为**候选 C · 学习投入诊断看板**，工程骨架已跑通，进入数据层。

## 本次迭代的可复用结论

| 结论 | 说明 |
|---|---|
| AI 给建议时必须显式标注建议性质 | 标注「仅建议」之后，仍然可能被后续步骤当既定前提用；要连「不得据此落地」一起约束 |
| 纠正越权要连「衍生污染」一起清 | 越权落点常常散布在仓库文件、日志、记忆三处，只回退一处等于没回退 |
| 判断依据本身是有价值的产出 | 本次「退路长度」「报错可复现性」两条判据，后来成了本人拍板的主要参考 |

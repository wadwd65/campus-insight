## 一、我的意图

上一版（prompt-005）是我让 AI "照参考站做"，它做了四层平铺视差。我当时没细看，交出去之后发现两个问题：

2. **整个东西还是"最基础的那一版"**：所有内容都感觉要重做

我给 AI 的核心纠正是一句方法论：

> 你参考那两个素材就是让你做一个**动态效果**，如果做不了的话，还要自己找点素材

也就是说：参考的价值是让我看"动态能做到什么程度"，**不是抄它的配方**。AI 之前理解成了后者。

还有两条对产品的判断：

> **答题应该是一个功能，而不是点进去就是答题**
> 里面那些答题的东西也不是那么直白，就是太没有东西了，就像我们**玻璃质感的手给它按上去**

> **地图是第一界面，答题是他的子端口，而不是主端口**

## 三、AI 的回应摘要

### 3.1 关键转折：真去看视频，而不是读归档的描述

AI 前面两版都错在同一件事上 —— **把参考当配方抄**。这次它换了做法：用 `bili-video-frame-extract` 技能 + 自己搭的抽帧台（`.workbuddy-gen/vid/serve.cjs`，零依赖、浏览器 canvas 抽帧）把 `BV16N41117xb` 的 0-30s **逐帧看了一遍**。

看完发现归档的拆解里有三处描述是错的，而且漏掉了最核心的机制：

| 归档里写的 | 实际是什么 |
|---|---|
| 「紫蓝破碎天空」（深色） | **浅紫→灰蓝的雾蒙蒙天空**，很亮很淡 |
| 「四层视差」（多层各自淡入） | **一整段不间断的推镜**穿过分层场景 |
| （没提） | **下落的光雨**贯穿全屏 + 蝴蝶/花瓣飘浮 |
| （没提） | 主角**就在场景里**，不是贴两边的照片 |
| （没提） | 前 6 秒**一个字都没有** |

核心机制的差别是可以写成公式的：

```
平铺视差：所有层在同一平面漂，深度靠"速度差"假装出来
推镜    ：各层按真实景深缩放，近处涨得快、远处涨得慢 —— 空间是真的
```

数学上就是「各层共享一个推进量 t，但各层的缩放系数不同」。

### 3.2 素材：自己生成，因为版权与"做不了"

- **参考站的图/音/字体版权归 lowiro，一个字节都不能进公开仓库**
- 在线生成了三张浅调场景图（天空雾层 / 破碎大教堂尖塔+悬浮碎玻璃 / 深色荆棘藤蔓前景）
- 处理链路：文生图 → 去水印 → 泛洪抠透明底 → WebP，三张共 **196 KB**

图像处理踩了三个真坑，每个都修掉了：
1. **去水印**：横向拉伸遇深色区域会糊成色块 → 改「上方同宽取纵向中位数」
2. **白晕**：只模糊 alpha 不够，白像素颜色还在 → 反解 `真色 = (像素色 − 白×(1−a)) / a`
3. **命名靠时间戳猜** → 改显式 MANIFEST 映射

### 3.3 三处架构改动

**① 平铺 → 推镜**（`introLayers.js` 完全重写）

```js
export const SCENE_LAYERS = [
  { id: 'sky',   depth: 0, zoom: 1.06 },  // 最远，几乎不动
  { id: 'arch',  depth: 1, zoom: 1.22 },
  { id: 'front', depth: 2, zoom: 1.52 },  // 最近，压过来
];
```

核心规则抽成纯函数（可断言）：

```js
export function layerTransform(layer, t) {
  const scale = 1 + (layer.zoom - 1) * clamped;
  const dir = layer.depth % 2 === 0 ? 1 : -1;   // 相邻层反向横移 = 交错
  return { scale, drift: layer.drift * clamped * dir };
}
```

驱动方式：一个 rAF 循环往容器写 CSS 变量 `--push`，各层在 CSS 里
`scale(calc(1 + (var(--zoom) - 1) * var(--push)))` —— **"近处涨得快"因此变成了数据上的层次关系**，而不是三条各写各的 `@keyframes`。

**② 深色 → 浅调**（`terminalTheme.js` 新增 `LIGHT`）

参考的入场是通透的浅紫雾，进去之后才是深色操作界面。**这个落差是有用的** ——它把「走进来」和「在里面操作」分成两种体验。

**③ 节拍 2100ms → 4600ms，分三幕**

| 幕 | 时间 | 内容 |
|---|---|---|
| 第一幕 | 0-1500ms | 纯环境（雾、建筑、光雨、飘浮物），**一个字都没有** |
| 第二幕 | 1500-3550ms | 文字逐行浮现（纹章→标语→标题→副标→说明） |
| 第三幕 | 4100ms | 入口出现 |

参考里前 6 秒屏幕上是空的，这里压到 1.5 秒 —— 仪式感要有，但评委的时间比视频观众贵。

**④ 地图升为主界面**（`App.jsx` 一行 + 两个新组件）


## 四、我发现的问题 / AI 的自我修正

### 4.1 ★ 差点把三张场景图删掉（最危险的一次）

`git rm` 两个立绘时，因为 `public/art/` 里只剩这三个文件，**整个目录被删掉了** —— 而三个场景素材虽然已经 commit，工作区里也没了。

当时的表象很能骗人：`git commit` 成功、`git log` 正常、commit stat 显示只删了 2 个文件。**如果不核对工作区，推送上去的网站会一张场景图都加载不出来 —— 入场直接退化成纯色 + 文字，而那是"看起来正常"的一种坏法。**

发现方式：`ls public/art/` 报目录不存在 → `git status` 显示三个 `D` → `git checkout HEAD -- public/art/` 恢复。

**教训**：`git rm` 在"删的是目录里最后几个文件"时，会连带把同目录其它已跟踪文件从工作区移除。删素材之后必须核对整条链路：`git ls-files` + 工作区 `ls` + HTTP 200 实测。

### 4.2 断言写法把"值不对"伪装成"变量没写进去"

`--push` 初始值的断言写成 `includes('--push: 0')`（带空格），但 React 序列化 inline style 时**不补空格**，实际输出是 `--push:0`。失败信息看起来像"变量没写进去"，实际是断言写错了。

这类坑在本项目已经是第三次（前两次是 React 的 `<!-- -->` 注释分隔符、`{n} 个人` 渲染成 `48<!-- --> 个人`）。**共同点：断言的字面串必须来自真实输出，不能凭语感写。**

### 4.3 亮度上限没设，光雨会糊住标题

`buildLightRain` 第一版 `opacity = 0.1 + depth*0.13 + rand*0.16`，depth=2 时最亮到 **0.52** —— 浅色天空上会糊成白杠。自检里那条「光雨亮度都很低」的断言抓出来了。

修正不是放宽阈值，而是改公式把上限压住（`0.08 + depth*0.09 + rand*0.14`，最高 0.31）。飘浮物同理（0.28+0.2+0.28 → 0.2+0.14+0.16）。**"上限"这件事必须由生成端保证，不能指望调用方裁剪。**

### 4.4 文字可读性 —— 只有真截图才看得出来（关键）

规则全绿、selftest 89 项全过，但**第一张实测截图里标题几乎读不出来**：

- 入场是浅色雾景，标题又落在建筑/光斑最亮处 → 「深色细衬线字压在浅色高光上」对比度不够
- 前景藤蔓是深色、又大又密，压在中央把标题吃掉
- 左下角按钮压在前景深色藤蔓上，整个糊掉

三处修正（都是实测驱动的）：
1. 前景层透明度压到 **0.55**（`.intro-layer-front`）—— 它是"穿过画面的前景"，本来不该是主体
2. 加**径向渐变底衬**（`.intro-scrim`）：只压中心、边缘完全透明 —— 既保住参考里最值钱的通透感，又让字读得清
3. 标题的光晕加第三层**往深色方向散**的阴影，把字从背景高光里"剥"出来

**这条最值得记**：selftest 能验"规则成立"，验不了"看起来对不对"。上一版每条规则都过，画面仍然是两张照片贴在两边。**视觉的东西必须真截图看，不能只靠断言。**

### 4.5 AI 报的模型名是编的

我让它推荐 Illustrious / NoobAI 系模型，它报了 WAI-illustrious / NoobAI-XL / Illustrious-XL —— **启动器列表里一个都没有**。

根因：它是从训练知识里报的，不是从启动器实际列表读的。我发截图之后核对确认：**列表里全是 SD1.5 时代模型**（anything v5、EkMix、Dreamlike、mignon、momocha、HD-2x、QuAn、ErieOrangeMix、ElyNightOrangeMix），没有 Illustrious/NoobAI/SDXL 系。

**教训**：涉及"某个软件里有什么"这种事实，必须去读那个软件的实际数据，不能凭模型知识答。

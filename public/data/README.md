# public/data/ · 数据文件

随代码提交、随构建产物一起发布的数据文件。评委 clone 仓库后**不需要自己去找数据**。

## 当前文件

| 文件名 | 用途 | 规模 |
|---|---|---|
| `问卷基准数据.csv` | 2000 人的模拟问卷作答，提供「你排在人群第几」的百分位基准 | 2000 行 × 7 列 |
| `示例-班级问卷.csv` | 供评委下载后试真入口（上传 → 群体画像） | 待做 |

## 字段（7 列，顺序可变）

| 列名 | 取值 |
|---|---|
| `编号` | `S0001` ~ `S2000`（可选列） |
| `深夜出没地` | 5 个选项之一 |
| `期末生存方式` | 5 个选项之一 |
| `宵夜频率` | 4 个选项之一 |
| `想加入的社团` | 5 个选项之一 |
| `经济状态` | 4 个选项之一 |
| `毕业最想带走` | 5 个选项之一 |

**只存原始作答，不存算好的属性值。** 这一条是刻意的：

1. 评审链路完整 —— 数据源（原始问卷）→ 计算（映射矩阵）→ 图表，官方要求的三段式有正式依据
2. 评委本人与这 2000 人**走完全相同的计算路径**，所以「你超过了 82% 的人」是算出来的，不是查表来的，口径必然一致
3. 数据层三件套可以 **100% 复用**

## ⚠️ 数据声明

**这是模拟生成的数据，不是真实调查结果，不含任何真实个人信息。**

由 `scripts/generate-survey-data.py` 按固定随机种子 `20260914` 生成，可完整复现。生成时按 **6 种人群亚型**（学霸型 / 社交型 / 运动型 / 夜猫型 / 干饭型 / 均衡型）加权采样，而不是每题独立均匀随机 —— 独立随机会让 2000 人在属性空间里挤成一团正态云，人人都接近 50 分位，「百分位」这个数就彻底失去了意义。

README、页面、技术文档**三处**都必须保留这项声明，不得暗示为真实统计。

## 容错

解析与清洗层（`src/lib/parseCsv.js` + `surveyClean.js`）要能吃下真实用户从 Excel 导出的脏文件：

| 情况 | 表现 |
|---|---|
| 带 BOM | 正常解析（Excel 导出几乎必带） |
| 全角空格 | 自动清除 |
| 列顺序不同 | 按列名识别，不依赖顺序 |
| 缺列 | 整份拒绝，**点名说缺哪一列** |
| 某行选项不在题目范围内 | 剔除该行，报告第几行、哪一列、原值是什么 |
| 空文件 / 只有表头 | 分别给出不同的提示语 |
